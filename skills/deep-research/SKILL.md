# deep-research — 팬아웃 + 적대적 검증 리서치

질문을 여러 검색 각도로 분해해 병렬 조사하고, 소스를 fetch해 **반증 가능한 주장**을 추출하고,
각 주장을 **적대적 다표결**로 검증한 뒤, 확신순으로 랭크한 **인용 리포트**로 합성한다.

**런타임 매핑 + 충실도 정직.** 이 스킬의 *로직*(Scope→Search→Fetch→Verify→Synthesize)은 런타임
무관이나, 구조적 병렬 실행은 런타임 프리미티브에 달렸다:
- **Claude Code**: 하니스에 번들 `deep-research` 워크플로가 있으면 **그걸 우선**
  (`Workflow({name:"deep-research", args:"<질문>"})` — 스키마 제약 에이전트 + 진짜 병렬 fan-out).
  없으면 아래 절차를 `WebSearch`·`WebFetch` + 병렬 `Task` 에이전트로 **수동** 수행.
- **Codex(OMX)**: OMX `autoresearch`/`autoresearch-goal`/`best-practice-research` 를 **우선** 사용.
  없으면 아래 절차를 Codex 웹 검색/fetch로 수동 수행.
- ⚠️ **충실도**: prose 수동 경로는 JS 워크플로의 스키마-제약 병렬 fan-out보다 **충실도가 낮다**
  (병렬성·정량 투표가 근사됨). 정밀 리서치가 핵심이면 위의 네이티브 워크플로/스킬을 우선하라.

## 언제 쓰나
- 여러 소스로 **깊이·교차검증**된 사실 기반 리서치 리포트가 필요할 때.
- 주장마다 출처·확신도가 붙은 결과가 필요할 때.

## 쓰지 않을 때
- 단발 사실 조회(웹검색 한 번이면 충분).
- 코드베이스 내부 조사(→ deepsearch/explore).
- 질문이 과소명세면 **먼저 2~3개 범위 질문**으로 좁힌 뒤 진행(예산·용도·지역 등).

## 절차 (5단계) — 수동 경로 기준

### 1. Scope
질문을 **~5개 검색 각도**로 분해(상호보완적 관점: 정의/현황·반대근거·정량데이터·사례·시간축 등).

### 2. Search
각도마다 **병렬** 웹검색(Claude=병렬 `Task`+`WebSearch`, Codex=병렬 조사). 각 에이전트는 서로의
결과를 모른 채 독립 탐색.

### 3. Fetch
URL 중복제거 후 상위 **≤15 소스**(`MAX_FETCH=15`) fetch → 각 소스에서 **반증 가능한 주장** 추출.

### 4. Verify (적대적)
주장마다(≤25개, `MAX_VERIFY_CLAIMS=25`) **3표 검증**(`VOTES_PER_CLAIM=3`): 각 검증자는 주장을
**반증하도록** 지시. **2/3 이상 반증(`REFUTATIONS_REQUIRED=2`)이면 주장 폐기**. 불확실하면 반증 기본값.
가능하면 검증자마다 다른 렌즈(정확성·출처신뢰·재현성).

### 5. Synthesize
의미 중복 주장 병합 → **확신순 랭크** → 소스 인용과 함께 리포트. 살아남은 주장·폐기된 주장·미해결
불확실성을 구분해 제시.

## 출력 형식
- **요약**: 핵심 발견 3~5개(확신도 표기).
- **본문**: 주장별 근거 + 출처(URL/제목) + 확신도. 상충 증거는 병기.
- **출처 목록**: fetch·인용한 소스.
- **한계**: 검증 폐기된 주장, 미해결 불확실성, 조사 못 한 각도.

## 함정
- **적대적 검증 생략 금지** — 그럴듯하나 틀린 주장이 살아남는다(2/3 반증 게이트가 핵심).
- **단일 검색 각도 의존 금지** — 한 관점은 반드시 놓친다(5각도 병렬).
- **충실도 과대주장 금지** — 수동 경로면 병렬성·정량투표가 근사임을 리포트에 밝힌다.
- **과소명세 질문 즉시 착수 금지** — 먼저 범위를 좁혀라.

ARGUMENTS: [리서치 질문] (과소명세면 먼저 범위 질문으로 좁힘)
