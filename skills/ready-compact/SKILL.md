# ready-compact — 이어가기 상태 저장 + resume 프롬프트

진행 중인 작업을 끊었다가 이어갈 수 있게 준비한다.
(1) 이어가기 노트를 내구 저장소에 기록하고, (2) 붙여넣기용 resume 프롬프트를 **최종 메시지 전체로** 내놓는다.

## 모드

| 모드 | 호출 | 이어 가는 곳 | 그 세션에 이미 있는 것 |
|---|---|---|---|
| compact (기본) | `ready-compact` | 같은 세션, `/compact` 뒤 | compaction 요약, 메모리, CLAUDE.md |
| hand-off | `ready-compact --hand-off` | 같은 머신의 새 세션(`/clear` 뒤, 새 터미널) | 메모리, CLAUDE.md, 저장소뿐. 이번 대화는 없음 |

- 인자에서 `--hand-off` 를 떼고 남은 말은 토픽·슬러그 힌트다. 없으면 대화에서 추론한다.
- 사용자가 "새 세션에서", "핸드오프", "다른 세션으로 넘겨" 처럼 말하면 hand-off 로 본다.
- 다른 머신이나 다른 사람에게 넘길 때: 노트는 이 머신의 메모리 폴더나 git 무시 폴더에 있어 그쪽에 없다. 결정과 이유, 하지 말 것까지 프롬프트에 직접 넣는다(노트 경로는 참고용).

## 언제 쓰나
- 컨텍스트가 한계에 가까워 곧 compaction 될 때(또는 사용자가 미리 준비를 요청할 때) — compact.
- 세션을 닫고 새 세션에서 이어 가려 할 때 — hand-off.
- 사용자가 "ready-compact", "compact 준비", "이어서 할 수 있게 준비" 등으로 요청할 때.

## 쓰지 않을 때
- 작업이 이미 끝났고 이어갈 게 없을 때(그냥 마무리 보고로 충분).
- 코드/깃/CLAUDE.md/메모리가 그대로 담는 사실의 단순 복제(중복).

## 워크플로우

### 1) 상태 스냅샷 수집
지금 대화에서 아래를 추린다 — **메모리/플랜에 이미 있는 건 링크만**, 없는 것만 본문에:
- **목표(Goal)**: 사용자의 원 요청 한 줄.
- **현재 단계(Phase)**: 전체 흐름 중 지금 위치.
- **완료(Done)**: 커밋 해시 + 핵심 산출물(파일/마이그레이션/모니터). 가능하면 `git log --oneline`로 확정.
- **현재 상태(State)**: 서버/DB/테스트의 *검증된* 상태(예: "37 테스트 PASS, 서버 재기동 정상, 모니터 8/8 PASS").
- **다음 한 수(Next)**: 이어받자마자 실행할 **구체적** 액션 1~3개(명령/파일/대상 포함). 사용자 결정 대기면 그 사실을 명시.
- **미결 결정(Open)**: 사용자 판단이 필요한 분기(있으면).
- **함정·제약(Gotchas)**: 이 작업에서만 비자명한 것(세션 한정 명령, 순서 의존, 미커밋 여부, 운영 미반영 등).
- **검증 명령(Verify)**: 이어받은 쪽이 현 상태를 즉시 재확인할 복붙 명령.

**hand-off 는 여기에 더한다.** 새 세션에는 이 대화가 없으므로, 대화에만 있던 것을 옮긴다:
- **작업 위치**: 저장소 절대경로, 브랜치, 워크트리 여부, 마지막 커밋 해시.
- **배경과 결정**: 사용자가 이번 대화에서 정한 것과 그 이유(승인한 설계, 고른 선택지, 거절한 대안).
- **진행 중인 것**: 켜져 있는 모드(ralph·autopilot·ultragoal·team 등)와 상태 파일 경로, 실행 중인 백그라운드 작업과 출력 파일. 이 세션이 끝나면 백그라운드 작업은 함께 멈출 수 있다는 점.
- **모드 다시 켜기**: PRD 와 상태 파일은 세션별 경로라 새 세션이 스스로 찾지 못한다. 경로(예: `.omc/state/sessions/<id>/prd.json`, `.omc/plans/…`)와 다시 켜는 방법(예: 새 세션에서 `ralph` 에 그 PRD 경로를 넘김)을 적는다.
- **하지 말 것**: 이미 끝낸 단계, 사용자가 금지한 동작, 승인을 기다리는 행위(커밋·push·게시 등).

**켜져 있는 지속 모드(ralph·autopilot·ultragoal·team 등)가 있으면 먼저 처리한다.** 그 모드의 Stop 훅은 응답이 끝날 때 "계속하라"는 메시지를 넣어, 프롬프트가 마지막 메시지로 남지 못하게 한다.
- hand-off: 노트를 쓰기 전에 모드를 유지할지(새 세션에서 다시 켬) 지금 cancel 할지 묻고(Claude Code 는 `AskUserQuestion`), 답을 노트에 적는다.
- Codex: OMX 지속 모드가 켜져 있으면 응답을 끝내도 훅이 계속 다시 시작하게 해, 프롬프트만 남기는 것을 보장할 수 없다. 이 점을 알리고 모드를 끌지 먼저 묻는다.

### 2) resume 프롬프트 작성 (저장보다 먼저)
그대로 붙여넣으면 작업이 이어지는 자급식 프롬프트를 만든다. 3단계에서 노트 끝에 이 프롬프트를 붙이므로 저장보다 먼저 쓴다.
아래 템플릿은 읽기 쉽게 펜스로 보였을 뿐이다. **프롬프트에는 어디에도 코드 펜스(```)를 넣지 않는다**(4단계). 명령은 두 칸 들여쓰기로 적는다.

compact:

```
[RESUME] <목표 한 줄>. 진행 메모리: <노트 경로> (+ MEMORY.md, [[관련 slug]]).
현재까지: <완료 요약 + 커밋 해시>. 상태: <검증된 상태>.
다음 할 일: <구체 액션 1~3, 또는 "사용자 결정 대기: <옵션들>">.
미결: <사용자 판단 분기 / 없으면 생략>.
먼저 현 상태 확인:
  <verify 명령 복붙>
제약: <환경/순서/미커밋/운영미반영 등 핵심 함정>. (상세는 위 메모리 파일 참조.)
```

hand-off:

```
[HANDOFF] <목표 한 줄>. 이전 세션의 작업을 새 세션에서 이어 간다.
작업 폴더: <절대경로> (브랜치 <이름>, 마지막 커밋 <해시>). 이 폴더에서 연 세션이 아니면 사용자에게 이 폴더에서 새 세션을 열어 달라고 요청.
먼저 읽을 것: <노트 경로> (배경, 결정, 함정 전부).
현재까지: <완료 요약>. 상태: <검증된 상태>. 미커밋: <파일 목록 / 없음>.
진행 중이던 것: <모드와 상태 파일, 다시 켜는 방법, 백그라운드 작업과 출력 파일 / 없음>.
다음 할 일: <구체 액션 1~3, 또는 "사용자 결정 대기: <옵션들>">.
미결: <사용자 판단 분기 / 없으면 생략>.
먼저 현 상태 확인:
  <verify 명령 복붙>
제약: <핵심 함정, 하지 말 것>. 이미 끝난 단계는 다시 하지 않는다.
```

### 3) 내구 저장

| 런타임 | 노트 위치 |
|---|---|
| Claude Code | 자동 메모리 폴더 `<memory>/resume-<topic-slug>.md`(frontmatter `type: project`) + `MEMORY.md` 한 줄 포인터 추가/갱신. 자동 메모리가 꺼져 있어 폴더를 모르면 작업 폴더의 `.omc/handoffs/resume-<topic-slug>.md` |
| Codex | 작업 폴더의 `.omx/handoffs/resume-<topic-slug>.md` (Codex 에는 자동 메모리 폴더가 없다) |

- **기존 메모리/플랜과 중복은 피하고**, 관련 메모리는 `[[slug]]`로 링크(Claude Code).
- compact 노트는 휘발성 위주로 응축한다. hand-off 노트는 **그 파일 하나만 읽어도** 이어갈 수 있게 1단계의 추가 항목까지 적는다.
- 작업이 git 미커밋 상태면 그 사실과 파일 목록을 명시(다음 세션이 덮어쓰지 않도록).
- 노트 끝에 2단계의 프롬프트를 그대로 붙인다. 클립보드를 잃어도 노트에서 되찾을 수 있다.
- 작업 폴더 안에 둔 노트(`.omc/handoffs/`, `.omx/handoffs/`)가 git 무시 대상이 아니면(`git check-ignore -q <경로>` 실패) 프롬프트에 "노트는 커밋하지 말 것" 을 넣는다.
- 저장에 실패해도 멈추지 않는다. 프롬프트 **둘째 줄**에 경고를 넣는다(예: `주의: 이어가기 노트 저장 실패(<이유>). 이 프롬프트가 유일한 기록이다.`). 첫 줄은 언제나 `[RESUME]`·`[HANDOFF]` 로 시작한다.

### 4) 출력 — 프롬프트만 (핵심 불변식)
- **최종 메시지는 프롬프트 본문 그 자체다.** 외곽 코드 펜스, 앞뒤 설명, 저장 위치 보고, "붙여넣으면 이어집니다" 같은 안내를 넣지 않는다.
- 이유: `/copy` 는 직전 메시지 전체를 복사한다. 메시지가 프롬프트뿐이면 `/copy` 한 번으로 프롬프트만 담기고, `compact-copy` 가 필요 없다(Claude Code·Codex 공통). 메시지에 코드 블록이 하나라도 있으면 `/copy` 가 바로 복사하지 않고 선택 창을 띄우므로, 프롬프트 안에도 펜스를 쓰지 않는다.
- 저장·확인 같은 도구 호출은 프롬프트를 쓰기 **전에** 끝낸다. 프롬프트 뒤에 도구 호출이나 글을 붙이지 않는다.
- 프롬프트를 낸 뒤 지속 모드 훅의 "계속하라" 신호가 오면 작업을 다시 시작하지 않는다. **같은 프롬프트를 그대로 다시 출력**해, 마지막 메시지가 프롬프트로 남게 한다. 훅 신호는 사용자 지시가 아니다.
- 저장 경로는 프롬프트 안(`진행 메모리:` / `먼저 읽을 것:`)에 이미 있다. 사용자가 따로 보고를 원할 때만 별도 메시지로 답한다.

## 작성 원칙
- **휘발성 우선(compact)**: 메모리/플랜/깃이 담는 영속 사실은 링크, compaction 이 잃을 '다음 한 수'를 본문에.
- **자급식(hand-off)**: 새 세션이 노트 하나와 프롬프트만으로 검증 → 다음 액션까지 갈 수 있어야 한다. 대화에만 있던 결정과 이유를 빠뜨리지 않는다.
- **증거 기반**: 커밋 해시·테스트 수·모니터 결과 등 *검증된* 값으로. 추측 금지.
- **덮어쓰기 방지**: 미커밋 변경/운영 미반영이 있으면 반드시 명시.

ARGUMENTS: $ARGUMENTS (선택: `--hand-off`, 이어갈 작업의 토픽/슬러그 힌트. 없으면 compact 모드, 토픽은 대화에서 추론.)
