# cleansing-memory: 메모리 파일 정리 (중복 최신본화·무손실 압축·replace 판별)

에이전트 런타임이 세션 시작마다 읽는 메모리 파일(Claude `MEMORY.md`·`CLAUDE.md`, Codex `AGENTS.md`)은
세션을 거듭할수록 **쌓이기만 한다.** 이 스킬은 그 파일들을 **관리 기준 threshold 안으로** 되돌린다:
(1) 중복을 정리해 **최신본만** 남기고, (2) 과도한 장문을 **내용 유실 없이** 간결화하고,
(3) **append 가 아니라 replace 로 관리할 정보를 판별**한다.

다루는 수치는 **문서화된 것만**이다. 한도가 문서화되지 않은 파일에는 한도를 지어내지 않는다.

**런타임:** 두 런타임의 메모리 모델은 **거의 닮지 않았다.** 한쪽 규칙을 다른 쪽에 옮기면 틀린다.
Claude = `CLAUDE.md` 한도 없음 + `MEMORY.md` 200줄/25KB + `@path` 4홉 import + AGENTS.md 미지원.
Codex = `AGENTS.md` 32768 B 프로젝트 예산 + 전역 파일 캡 없음.
그래서 이 스킬은 파일마다 **그 파일에 문서화된 한도만** 적용한다. 공통 규칙을 만들지 않는다.

## When to use
- 메모리 파일이 커져 **시작 컨텍스트**를 잠식할 때.
- 세션이 쌓여 같은 사실의 **옛 버전과 새 버전이 공존**할 때(상충 지시).
- Codex 프로젝트 `AGENTS.md` 체인이 **32768 B 에 근접·초과**해 조용히 잘릴 때.
- Claude auto-memory `MEMORY.md` 가 **200줄 또는 25KB 에 근접**할 때.
- dual-runtime 저장소에서 Claude 쪽과 Codex 쪽 메모리 파일이 **서로 다른 사실**을 말할 때.

## When NOT to use
- **아직 안 쓴 지식을 남기려는 것** → OMC `remember`. 경계가 헷갈리기 쉬우니 분명히 한다:
  `remember` 는 **쓰기 측**(무엇을 기억할지 결정해 남긴다), cleansing-memory 는 **GC 측**(이미 쌓인 걸 정리한다).
  `remember` 에는 크기·dedup 메커닉이 **0** 이다. 남길 거면 remember, 남은 걸 줄일 거면 이 스킬.
- **Claude 에서 코드베이스 유도분 트림** → `/doctor` 가 v2.1.206+ 에서 **이미 제안한다. 그쪽을 쓰라.**
  (디렉터리 구조·의존성 목록·아키텍처 개요처럼 코드베이스에서 유도 가능한 내용.) 여기서 재구현하지 않는다.
  단 `/doctor` 는 **Claude 전용**이라 Codex 의 `AGENTS.md` 엔 대체재가 없다.
- **한도에 여유가 큰 파일** → 손대지 마라. 압축은 공짜가 아니라 정보 손실 위험을 감수하는 행위다.

## threshold (검증된 것만)
확인 시점: **2026-07-16 / codex-cli 0.142.5 / Claude Code 2.1.211.**

| 파일 | 문서화된 한도 |
|---|---|
| Claude `MEMORY.md` | **200줄 OR 25KB 중 먼저.** 유일한 문서화된 하드 로드 게이트 |
| Claude `CLAUDE.md` | **없음.** 문서: "길이와 무관하게 전부 로드". 200줄은 soft target |
| Codex `AGENTS.md` (프로젝트) | **32768 B (32 KiB)** = `project_doc_max_bytes` 기본값 |
| Codex `~/.codex/AGENTS.md` (전역) | **캡 없음.** 별도 provider 가 통째로 read |
| agents.md 스펙 | **없음.** 파일명·중첩·마크다운만 표준화 |

- **CLAUDE.md 에 캡을 제시하면 날조다.** 문서화된 바이트 한도가 존재하지 않는다.
  정직한 진술은 "크면 줄이는 게 낫다"까지고, "N 을 넘으면 잘린다"는 **거짓**이다.
- **스코프 오류 주의**: 25KB 는 `MEMORY.md` **단독**에 걸린다. auto-memory **디렉터리 합계가 아니다.**
- **바이트가 맞고 토큰은 틀리다**: 런타임이 강제하는 건 바이트, 그리고 줄-OR-바이트다.
- **버전 고정 주의**: 32768·25KB/200줄·4홉은 **전부 버전 고정 사실**이다. 커뮤니티 출처는 **이미** 서로
  불일치한다(import 깊이를 4홉보다 크게 적은 글이 돌아다닌다). 보고할 때 **확인 시점을 같이 적고**,
  다른 버전에서는 1차 출처로 재확인하라.

## 메커니즘 (모르면 안전하게 못 자른다)
- **CLAUDE.md 로드 순서**(전부 concat, **override 없음**): managed policy → user `~/.claude/CLAUDE.md`
  → project `./CLAUDE.md` 또는 `./.claude/CLAUDE.md` → local `./CLAUDE.local.md`.
  뒤가 앞을 덮지 않는다. **더해진다.** "뒤에 쓴 게 이긴다"고 가정하면 상충이 안 지워진다.
- **`@path` import 재귀 깊이 = 4홉.** 코드 스팬·펜스 안의 `@README` 는 **리터럴**이라 import 되지 않는다.
- **Claude Code 는 AGENTS.md 를 읽지 않는다.** 문서화된 interop = CLAUDE.md 에 `@AGENTS.md` import 또는
  심볼릭 링크. dual-runtime 저장소에서 AGENTS.md 만 고치면 **Claude 쪽엔 아무 효과가 없다.**
- **Codex 프로젝트 discovery**: 루트→cwd 순회, **디렉터리당 첫 매칭 파일명 하나만**. 루트부터 concat.
- **`project_doc_max_bytes = 0` 이면 AGENTS.md 프로젝트 문서 로딩이 완전히 꺼진다.**
- **auto-memory 위치**: `~/.claude/projects/<project>/memory/`. git repo 기준이라 worktree 가 공유한다.
  `autoMemoryDirectory` 로 변경, `autoMemoryEnabled:false` 또는 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` 로 비활성.
  기본 켜짐·머신 로컬.

## 워크플로

### 1. 인벤토리 (읽기 전용)
대상과 **실제 크기**를 먼저 잰다. 추정 금지.
- Claude: `~/.claude/CLAUDE.md`, `./CLAUDE.md` 또는 `./.claude/CLAUDE.md`, `./CLAUDE.local.md`,
  managed policy, auto-memory `MEMORY.md`.
- Codex: `~/.codex/AGENTS.md`(캡 없음), 프로젝트 루트→cwd 의 `AGENTS.md` 체인.

```bash
wc -lc <파일>   # 줄 수와 바이트를 같이 본다. 문자 수(-m)가 아니라 바이트다
```
- `@path` import 를 **4홉까지** 따라가 실제 로드 총량을 본다. 코드 스팬·펜스 안의 `@...` 는 세지 마라.
- **한도에 여유가 크면 여기서 멈춘다.** 보고만 하고 끝낸다.

### 2. 중복 정리 → 최신본만
1차 근거: 공식문서가 **"메모리 파일 간 상충하는 지시"** 를 주기적 검토가 필요한 **실패 모드로 명시**한다.
커뮤니티 heuristic 이 아니라 문서화된 실패 모드다.
- 같은 사실의 항목이 여럿이면 **최신본 하나만** 남기고 옛 값은 지운다.
- 로드 체인은 override 가 없으니, user 와 project 가 상충하면 **둘 다 살아서** 모델에 들어간다.
  직접 지워야 사라진다.
- 어느 쪽이 최신인지 **모르면 지우지 말고 물어라.** 모르고 지우는 건 정리가 아니라 도박이다.

### 3. append→replace 판별 (이 스킬의 알맹이)
- **replace 대상 = 현재 상태를 서술하는 사실**(버전·설치 위치·진행 지점). 새 값이 옛 값을 **무효화**한다
  → 덮어쓴다. 이력을 남기려고 append 하면 파일이 단조 증가하고 모델은 **옛 값도 사실로 읽는다.**
- **append 대상 = 일어난 사건의 기록**(감사 결과·결정 근거). 나중 사건이 앞 사건을 무효화하지 않는다
  → 쌓되 요약해 topic 파일로 민다.
- 애매하면 질문 하나로 가른다: **"새 값이 나오면 옛 값은 틀린 것이 되나?"** 그렇다 → replace.
  둘 다 여전히 참이다 → append.

### 4. 무손실 간결화 + topic 파일 분산
살아남은 최적화는 이것이다. **auto-memory topic 파일은 시작 시 로드되지 않는다**(문서화된 메커니즘).
`MEMORY.md` **만** 로드된다.
- → `MEMORY.md` 인덱스는 **얇게**, 상세는 **topic 파일로** 민다. 정보는 그대로 두고 **시작 컨텍스트
  비용만 실제로 제거**한다. 삭제가 아니라 **이동**이라 무손실이다.
- → 200줄/25KB 게이트도 `MEMORY.md` **단독**에 걸리므로 이동만으로 통과한다.
- 간결화는 **표현**을 줄이는 것이지 **사실**을 줄이는 게 아니다. 서술을 줄이고 구체값(버전·경로·수치·결정)은
  남긴다.
- 이 스킬이 소유하는 연산은 셋뿐이다: **중복 최신본화 + 무손실 압축 + append→replace 판별.**
  Claude 의 코드베이스 유도분 트림은 `/doctor` 몫이다(위 "When NOT to use").

### 5. 안전한 쓰기
- **문자 경계에서 자르고 한도에 여유를 둔다.** 정확히 N 바이트로 맞추지 마라("함정" 참조).
- 쓰기 전에 diff 를 보여주거나 원본을 백업한다. 메모리 파일 손실 = **세션 간 지식 손실**이다.
- `project_doc_max_bytes = 0` 으로 "해결"하지 마라. 로딩이 통째로 꺼진다.
- AGENTS.md 만 고치고 Claude 도 좋아졌다고 하지 마라. **Claude Code 는 AGENTS.md 를 읽지 않는다.**

### 6. 검증 (보고 의무)
쓰고 나서 **다시 재고** 보고한다. 추정 금지.
- **before/after 바이트·줄 수**를 파일별로. 토큰이 아니라 바이트다.
- 한도 대비: `MEMORY.md` 200줄 OR 25KB, 프로젝트 `AGENTS.md` 체인 32768 B.
- **UTF-8 무결성**: 결과 파일에 **U+FFFD** 가 있는지 확인한다. 있으면 절단이 문자를 쪼갠 것이다. 되돌려라.
- **유실 점검**: replace 로 지운 게 정말 무효화된 옛 값인지, topic 파일로 민 내용이 **실제로 거기 있는지**.
- **확인 시점 명시**: 기준 수치는 codex-cli 0.142.5 / Claude Code 2.1.211 (2026-07-16).
- **자가 무효화 위험**을 보고에 적는다("함정" 참조).

## 함정
- **UTF-8 손상 (Codex)**: Codex 는 **raw 바이트 버퍼를 자르고 나서** `from_utf8_lossy` 를 씌운다.
  한글은 **3바이트/자**라 경계 문자가 쪼개져 **U+FFFD 로 깨진다.** 절단은 **조용하고 파일 중간**에서
  일어나며 TUI 에 **경고가 뜨지 않는다.** → "정확히 N 바이트로 자르는" 방식은 **스스로 손상을 만든다.**
  반드시 **문자 경계에서 자르고 여유를 둬라.**
- **자가 무효화**: auto-memory 는 Claude 가 쓰고 **세션 중에도 다시 쓴다.** `MEMORY.md` 정리가 같은
  세션이나 다음 세션에 **조용히 재팽창·되돌려질 수 있다.** 1회성 이벤트로 취급하지 마라. 정리 결과가
  유지되길 원하면 auto-memory 비활성 스위치가 존재한다는 사실을 사용자에게 알리고, **결정은 사용자에게** 맡겨라.
- **CLAUDE.md 캡 날조**: 다시 적는다. CLAUDE.md 에 **문서화된 바이트 한도가 없다.** 캡 수치를 제시하는
  순간 그건 **날조**다. 200줄은 soft target 이지 강제가 아니다.
- **스코프 오류**: 25KB 를 auto-memory **디렉터리 합계**에 적용하면 **없는 위반을 만들어낸다.**
  topic 파일은 시작 시 로드조차 되지 않는다.
- **토큰으로 판정**: 게이트는 바이트와 줄-OR-바이트다. 토큰 추정은 게이트와 **무관하다.**
- **Codex 문서의 오해 유발 프레이밍**: 공식문서가 전역 → 프로젝트 순서 리스트로 서술해 **전역 파일이
  32 KiB 예산을 쓰는 것처럼 읽힌다.** 전역은 이 예산과 무관하고 캡이 없다. **프로젝트 예산에서 빼지 마라.**
- **`@` 리터럴 오독**: 코드 스팬·펜스 안의 `@README` 는 import 가 아니다. import 로 착각해 손대지 마라.

## 원칙
- **날조 금지.** 문서화된 한도가 없으면 "없다"고 말한다. 없는 수치를 만들지 않는다.
- **재기 전에 자르지 않는다.** 인벤토리 없는 압축은 추측이다.
- **무손실 우선.** 지우기 전에 옮긴다. 지우는 건 **무효화된 옛 값**뿐이다.
- **바이트로 말한다.** 토큰으로 말하지 않는다.
- **런타임을 섞지 않는다.** Claude 규칙을 Codex 에 적용하지 않는다. 반대도 같다.
- **겹치면 양보한다.** `/doctor` 가 이미 하는 일은 `/doctor` 에 맡긴다.
- **수치엔 확인 시점을 붙인다.** 버전이 바뀌면 사실도 바뀐다.

ARGUMENTS: [--dry-run] [--claude|--codex] [대상 파일/경로] (없으면 현재 프로젝트·전역의 Claude·Codex 메모리 파일 전체를 인벤토리)
