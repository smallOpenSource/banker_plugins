# wbs-gen: WBS 간트 차트(XLSX, HTML)

WBS 와 일정을 받아 간트 차트 한 장을 XLSX 와 HTML 로 만든다. 답변은 한글.
모양은 엑셀로 직접 그린 한 장짜리 간트와 같다: 1행 제목, 2~3행 머리글(8열 + 주와 날짜), 틀 고정 8열 3행, A3 가로 한 장 너비 인쇄.

## 원칙

- **설치와 내려받기가 없다.** 도우미는 Node 표준 모듈만 쓴다(XLSX 도 직접 씀). 인터넷을 쓰는 곳은 `holidays` 하나이고, 닿지 않으면 사용자에게 묻는다.
- **막대는 셀 채움이다.** 조건부 서식과 수식을 쓰지 않아 어느 뷰어에서나 같게 보인다. 일정이 바뀌면 계획 파일을 고치고 다시 만든다.
- **영업일은 도우미가 센다.** 토, 일과 공휴일을 뺀 날만 날짜 열이 되고, 일수 칸도 그 수다. 사람이 적은 일수를 옮기지 않는다.
- **WBS 와 일정은 나누어 적는다.** WBS 번호와 작업 이름은 산출물이고, 시작, 종료, 선행은 일정이다. 제약사항 같은 메모 행은 WBS 번호 체계 밖 묶음(예: `C`, `P`)으로 둔다.
- 있는 파일을 덮어쓰지 않는다. 같은 이름이 있으면 묻고, 허락을 받은 뒤에만 `--force` 를 준다.
- 계획 파일과 출력에 비밀값을 넣지 않는다.

## 인자

| 인자 | 뜻 |
|---|---|
| `--xlsx`, `--html` | 낼 형식. 둘 다 없으면 둘 다 냄 |
| `--out <폴더>` | 출력 폴더. 없으면 지금 작업 폴더 |
| `--plan <plan.json>` | 이미 있는 계획 파일을 씀. 없으면 대화와 자료로 새로 씀 |

## 도우미

`G="<S>/scripts/wbs-gen.mjs"`. 머리 주석이 전체 사용법이다.

| 명령 | 하는 일 | 종료 코드 |
|---|---|---|
| `node "$G" example` | 예시 계획(JSON)을 냄. 계획 파일의 틀로 씀 | 0 |
| `node "$G" holidays --from <YYYY-MM-DD> --to <YYYY-MM-DD>` | 기간 안 한국 공휴일을 `MM/DD 이름` 줄과 마지막 줄 `HOLIDAYS MM/DD, ...` 로 냄. 기념일(어버이날 등)은 빼고 공휴일만 | 0, 닿지 못하면 3 |
| `node "$G" check --plan <plan.json>` | 계획을 검사하고 `OK 영업일 N ...` 한 줄을 냄 | 0, 계획 오류 1 |
| `node "$G" build --plan <plan.json> --out <파일.xlsx> --out <파일.html>` | 파일을 만듦. 있는 파일은 `--force` 없이 두고 2 로 끝남 | 0, 계획 오류 1, 사용법과 파일 오류 2 |

- `--holidays "8/17, 10/5"` 는 계획의 `holidays` 를 그 값으로 바꾼다. `check`, `build` 둘 다 받는다.
- `holidays --ics <파일>` 은 저장해 둔 달력 파일(.ics)을 읽는다. 사내망에서 다른 경로로 받은 달력을 쓸 때다.

## 계획 파일(plan.json)

`node "$G" example` 이 낸 틀을 고쳐 쓴다. 날짜는 `YYYY-MM-DD` 나 `M/D` 이고, `M/D` 는 프로젝트 기간 안의 해로 읽는다(12/20~01/15 이면 `1/5` 는 다음 해).

| 칸 | 뜻 |
|---|---|
| `title`, `subtitle` | 1행 제목과 메모. 제목 줄에 기간, 영업일 수가 함께 들어감 |
| `start`, `end` | 기간. `YYYY-MM-DD` |
| `holidays` | 공휴일. `"8/17, 10/5"` 같은 글이나 배열. `"없음"` 은 없음 |
| `gates` | `[{ "date", "label" }]`. 그 날짜 열 왼쪽에 빨간 수직선 |
| `parts` | `{ "<id>": { "name", "light", "dark", "legend" } }`. `light` 는 묶음 행 바탕, `dark` 는 막대. 색은 6자리 16진수. `legend: false` 면 범례에서 뺌 |
| `bars` | 우선순위별 막대 색. 예: `{ "선택": "FAD7A0", "준비": "D5DBDB", "마무리": "34495E" }`. 파트 색보다 앞섬 |
| `rows` | 행 목록. 아래 표 |
| `legend` | 범례에 더할 항목 `[{ "color", "label", "dotted" }]`. 파트 색, ◆, 게이트 선은 자동으로 들어감 |
| `notes` | 아래 메모 `[{ "heading", "lines" }]`. 예: `[우선순위]`, `[미확정]`, `[가정·변경]` |
| `sheet` | 시트 이름. 없으면 `WBS 간트` |

`rows` 의 `kind`

| kind | 쓰는 칸 | 그림 |
|---|---|---|
| `group` | `wbs`, `task`, `owner`, `part` | 행 전체를 파트의 연한 색으로 칠함 |
| `task` | `wbs`, `task`, `owner`, `priority`, `pending`, `start`, `end`, `part`, `bar` | 시작부터 종료까지 막대. 일수 칸은 그 사이 영업일 수 |
| `constraint` | `task` 칸들과 `date`(또는 `start`, `end`) | 종료 날짜에 ◆ 와 점선 테두리. 개발이 아닌 외부 선행 |
| `milestone` | `wbs`, `task`, `date` | 그 날짜에 ◆ |

시작, 종료, 마일스톤, 게이트 날짜가 주말이나 공휴일이면 오류다. 기간 중간의 공휴일은 그냥 열에서 빠진다.

## 절차

### 1. 자료 모으기
- 사용자가 준 WBS(표, 문서, 기존 엑셀, 말로 한 설명)를 읽는다. 기존 xlsx 는 읽기만 하고 고치지 않는다.
- 아래가 없으면 한 번에 묻는다: 기간(시작, 종료), 작업 목록과 담당, 각 작업의 시작과 종료, 마일스톤, 게이트. 파트 구분과 색은 묻지 않고 예시 색을 쓴다.
- 날짜가 정해지지 않은 작업은 `pending` 칸에 기다리는 것을 적고, 가정한 날짜는 `notes` 의 `[가정·변경]` 에 적는다.

### 2. 공휴일
1. `node "$G" holidays --from <start> --to <end>` 를 돈다.
2. 종료 코드가 0 이면 나온 목록을 보여 주고 확인 질문으로 묻는다: 이대로, 더하거나 빼기(그다음 `M/D, M/D` 를 받음).
3. 종료 코드가 3 이면(인터넷에 닿지 못함, 망분리, 프록시, Codex 승인 거절) 사용자에게 기간 안 공휴일을 `M/D, M/D` 로 받는다. 없으면 `없음`.
4. 확정한 값을 계획의 `holidays` 에 적는다. 회사 휴무일처럼 공휴일이 아닌 쉬는 날도 여기에 더한다.

### 3. 계획 파일 쓰기
- 출력 폴더에 `<이름>-wbs.json` 으로 쓴다. 이름은 제목에서 짧게 만든다. 같은 이름이 있으면 묻는다.
- `node "$G" check --plan <파일>` 이 0 이 될 때까지 고친다. 오류 줄은 어느 행의 무슨 칸인지 알려 준다. 경고(기간 밖 공휴일)는 보고에만 적는다.

### 4. 만들기
- `node "$G" build --plan <파일> --out <이름>-wbs.xlsx --out <이름>-wbs.html` 을 돈다. 형식 인자를 받았으면 그 형식만 준다.
- 종료 코드 2 에 `--force` 안내가 나오면 덮어쓸지 묻고, 허락을 받은 뒤에만 `--force` 를 더해 다시 돈다.

### 5. 확인
- `build` 출력의 `OK 영업일 N, 주 W, 행 R, 작업 T, ◆ M, 게이트 G` 를 계획과 대조한다. 영업일 수는 기간과 공휴일로 맞는지, 작업 수와 ◆ 수가 계획 행 수와 맞는지 본다.
- 브라우저를 쓸 수 있으면 HTML 을 열어 한 번 본다. 쓸 수 없으면 보았다고 적지 않는다.

## 보고

- 만든 파일의 절대경로
- 기간, 영업일 수, 뺀 공휴일(`MM/DD 이름`, 사용자가 입력했으면 입력값)
- 행 수, 작업 수, 마일스톤 수, 게이트
- 가정한 날짜와 확인하지 못한 것(`공휴일 미확인`, 브라우저로 보지 않음 등)
- 다음 행동이 있으면 마지막 줄에. 예: "일정이 바뀌면 `<이름>-wbs.json` 을 고치고 다시 부르십시오."

## 함정

- `holidays` 가 0 으로 끝나도 목록을 그대로 믿지 않는다. 임시공휴일이 늦게 들어갈 수 있으니 늘 사용자 확인을 받는다.
- 토요일 공휴일(예: 08/15)도 목록에 나온다. 원래 날짜 열에 없으므로 그대로 두어도 된다.
- 막대를 셀 채움으로 그렸으므로 엑셀에서 날짜 칸만 고치면 막대가 따라가지 않는다. 일정은 계획 파일에서 고친다.
- XLSX 의 글꼴은 `맑은 고딕` 이다. 그 글꼴이 없는 환경(macOS 의 LibreOffice 등)에서는 한글이 다른 글꼴로 보이거나 빠질 수 있다. 파일에는 글이 들어 있다.
