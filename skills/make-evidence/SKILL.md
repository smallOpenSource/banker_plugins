# make-evidence: 실행으로 만드는 증거 문서 여섯

구현한 서비스가 README 의 요구를 지키는지, 실제로 실행한 결과로 보이는 문서 여섯을 만든다.
문서는 `docs/evidence/` 에, 판정기는 `tests/oracle/` 에 쓰고 커밋한다. 답변은 한글.

## 원칙

- **수치는 손으로 쓰지 않는다.** 시간, 목적값, 차이, 통과 수, 건수는 스크립트가 로그에 `METRIC <이름>=<값>` 줄로 찍고, 문서는 그 값을 `` `<이름>=<값>` `` 으로 자릿수 그대로 옮긴다.
  - 이름에는 점이 하나 이상 있다(예: `scale.x5.median_s`). 점 없는 `exit=0` 같은 코드 표기는 수치로 보지 않는다.
  - 반올림이나 단위 바꾸기는 스크립트가 해서 찍는다. 측정 스크립트는 상수를 찍지 않는다. 로그를 손으로 쓰거나 고치지 않는다.
  - 시험 통과 수와 종료 코드는 `run` 이 로그 끝에 `METRIC run.exit=`, `METRIC run.tests.pass=` 처럼 찍는다(node --test, pytest, jest).
  - METRIC 을 찍는 코드는 `docs/evidence/scripts/` 의 파일에 둔다. 명령 줄에 `METRIC` 글이 든 로그(`node -e "console.log('METRIC ...')"` 등)는 `check` 가 거부한다.
- **문서마다 실행 명령과 로그 경로를 적는다.** 수를 적은 줄에는 그 로그 경로를 함께 적는다. 도우미 `check` 가 그 로그에서 같은 줄을 찾는다.
- **실행하지 못한 것은 `미검증` 과 까닭이다.** 추정값, 예상값, 다른 시험의 결과로 채우지 않는다.
- **미구현을 숨기지 않는다.** README 요구 가운데 구현하지 않은 것은 `trace.md` 에 `미구현` 과 이유로 남긴다.
- **구현을 고치지 않는다.** 결함을 찾으면 그대로 기록하고 사용자에게 알린다. 고칠지는 사용자가 정한다. 고친 뒤 다시 부르면 고치기 전 로그도 남긴다.
- **설치하거나 내려받지 않는다.** 없는 도구(브라우저, DB 클라이언트, 시험 도구)가 필요한 칸은 `미검증(<도구> 없음)` 이다. `npm install`, `pip install`, `npx playwright install`, 이미지 받기를 하지 않는다.
- **운영 서버, 운영 DB, 남의 서비스에 보내거나 쓰지 않는다.** 로컬 서버라도 설정이나 환경 변수가 그런 곳을 가리키면 먼저 사용자에게 묻는다. 구현을 띄우는 모든 실행(판정기 기준선과 버그 셋, 종단 시험, 규모 측정)에 같다.
- **사용자의 작업 트리를 건드리지 않는다.** 버그는 별도 작업 트리에서만 넣는다. `git checkout --`, `git restore`, `git stash`, `git clean`, `git reset --hard` 를 쓰지 않는다.
- 로그와 문서에 비밀값을 넣지 않는다. 도우미가 명령 줄과 출력의 흔한 비밀값 꼴(`DB_PASSWORD=`, `--token`, URL 의 비밀번호, 개인 키 등)을 `***` 로 가리고 그 수를 `# redacted=<n>` 로 남긴다. `commit` 은 비밀값 꼴이 남은 파일을 거부한다. METRIC 이름에 password, secret, token, key 를 쓰지 않는다(가림에 걸림).

## 도우미

`E="<S>/scripts/evidence.mjs"`. Node 만 쓰고 네트워크를 쓰지 않는다. `node "$E" --help` 가 전체 사용법이다.

| 명령 | 하는 일 |
|---|---|
| `run --log <파일> [--timeout <초>] [--cwd <폴더>] [--shell] -- <명령...>` | 명령을 돌려 로그를 남긴다. 첫 줄은 다시 돌릴 수 있게 인용한 명령, 둘째 줄은 `# head= dirty= at= node= os= cwd=`, 끝은 `exit=<코드>` 와 `METRIC run.exit=`. 명령의 종료 코드를 그대로 돌려준다. 입력은 닫혀 있고, 시간 제한(기본 300초)에 걸리면 프로세스 트리를 끝내고 `exit=timeout(<초>s)`, 종료 124. 출력을 쥔 채 떨어져 나간 자손은 기다리지 않는다(`# orphan-output=yes`) |
| `serve --log <파일> --pid <파일> --ready <URL> -- <명령...>` / `stop --pid <파일>` | 서버를 띄워 URL 이 답할 때까지 기다리고, 끝에 트리째 내린다. URL 이 이미 답하면 띄우지 않고, 기다리는 동안 서버가 끝나면 `not-ready(exited <코드>)`. 먼저 죽은 서버는 `exit=gone-before-stop` |
| `precheck` | 스테이징된 변경(`STOP`), 증거 밖의 바뀐 파일(`ASK dirty`), 이 컴퓨터 밖 주소(`ASK host`, 값은 안 보임)를 보인다. 주소는 네 단계 아래까지의 설정 파일과 환경 변수에서 찾는다. 환경 변수는 저장소가 이름을 부르는 것과, 프레임워크와 DB, 메시지 라이브러리가 스스로 읽는 이름(`SPRING_*`, `QUARKUS_*`, `ConnectionStrings__*`, `PG*`, `MYSQL_*`, `DATABASE_*`, `REDIS*`, `MONGO*`, `KAFKA_*` 등)을 묻고, 그 밖은 `NOTE host` 로만 보인다. 비밀번호와 토큰 이름의 변수는 값을 읽지 않는다. compose 서비스 이름 밖의 점 없는 이름도 묻는다. 결정할 것이 있으면 종료 3 |
| `room`, `collect --room <폴더> [--replace]` | 판정기 작성용 방(저장소 밖 임시 폴더)에 요구 문서와 담당자 사실만 넣고(방의 기록 파일은 방 밖), 끝나면 방의 `tests/oracle/` 만 가져온다. 방에 다른 파일이 생겼거나 입력이 바뀌었으면 거부(종료 1). 이미 판정기가 있으면 `--replace` 때만 바꾸고 이전 판정기 커밋을 찍는다 |
| `worktree [--link <폴더>]...`, `worktree --remove <폴더>`, `bug --worktree <폴더> --name <이름> [--kind <종류> --baseline <로그>] -- <판정기 명령...>` | HEAD 의 별도 작업 트리를 만들고(추적되지 않는 의존 폴더는 `--link` 로 이음, 빌드 결과와 `.env` 는 거부), 거기서 판정기를 돌리고, 패치와 로그를 남기고, 작업 트리를 지운다(거부돼도 지움). 사용자 작업 트리(추적 파일의 내용과 추적되지 않는 파일)와 링크한 폴더가 그대로인지 확인한다. 무시된 파일과 DB 는 확인 범위 밖이다 |
| `check [--tracked]`, `count --doc <파일>` | 문서의 `` `이름=값` `` 을 가리킨 로그의 `METRIC 이름=값` 줄과 정확히 대조한다. `run` 이 만든 로그만 받는다. `` `이름=값` `` 밖의 숫자는 로그 경로가 있든 없든 `WARN` 이고, 오류나 경고가 하나라도 있으면 종료 1. `count` 는 trace 표의 `상태` 칸(머리 줄로 찾음)을 세어 METRIC 줄로 찍고, 넷 가운데 하나가 아닌 행이 있으면 종료 1 |
| `commit --message <글> [--paths <경로>]... [--accept <파일:줄>]...` | 기본 `docs/evidence`, `tests/oracle` 만 커밋한다. 다른 스테이징된 변경이 있으면 거부. `.gitignore` 에 걸린 파일은 `docs/evidence/logs/` 의 `.log`, `.patch`, `.md` 만 넣는다. `.env`, 5MB 넘는 파일, 비밀값 꼴이 남은 줄(`--accept` 로 사용자가 확인한 자리는 빼고)이 있으면 거부. 커밋 훅은 우회하지 않는다 |

로그 이름은 `docs/evidence/logs/<문서>-<무엇>-{ts}.log` 다. `{ts}` 는 밀리초까지의 UTC 시각이고, 같은 이름은 덮어쓰지 않는다. 문서가 가리키는 로그가 결과를 내는 로그이고, 다시 돌린 로그도 지우지 않는다.

판정기는 판정마다 `ORACLE <constraint|objective|permission> <PASS|FAIL|ERROR> <사례 이름> [설명]` 한 줄을 찍는다. 사례 이름은 공백 없는 한 낱말이다. `bug` 는 이 줄로 판정한다.

## 진행

순서가 중요하다. 판정기 작성자에게 구현 정보가 가지 않도록, 구현을 읽기 전에 0~3 을 한다.

`git ls-files tests/oracle` 이 비어 있지 않으면(앞서 `--oracle-only` 로 판정기를 커밋함) 1~3 의 작성은 건너뛴다. 3 의 순서 로그만 남기고, 판정기 커밋 뒤 요구 문서나 담당자 사실이 바뀌었는지 `git diff <판정기 커밋> -- README.md docs/evidence/owner-facts.md` 를 `run` 으로 남긴다. 바뀌었으면 그 사실을 `verify.md` 에 적는다.

### 0. 사전 확인

```bash
node "$E" run --log 'docs/evidence/logs/precheck-{ts}.log' -- node "$E" precheck
```

- `STOP staged`: 사용자가 스테이징한 변경이 있다. 이 스킬은 스테이징을 풀지 않는다. 사용자에게 알리고 멈춘다.
- `ASK dirty`: 커밋하지 않은 변경이 있다. 묻는다: 사용자가 커밋한 뒤 다시 부름(권장), 또는 그대로 진행. 그대로 진행하면 문서마다 "커밋하지 않은 변경 위에서 실행함(precheck 로그)" 을 적는다. 판정기와 버그 시험은 늘 HEAD 의 별도 작업 트리에서 돈다.
- `ASK host`: 설정이나 환경 변수가 이 컴퓨터 밖의 DB 나 서비스를 가리킨다. 묻는다. 허락이 없으면 구현을 띄우지 않는다. 판정기 기준선과 버그 셋, `flow.md`, `scale.md` 의 측정이 모두 `미검증(비로컬 설정)` 이다.
- `NOTE host`: 저장소가 이름을 부르지 않는 환경 변수의 주소다. 서비스나 그 라이브러리가 그 변수를 읽는다면 `ASK host` 와 같이 묻는다.
- **구현 전인지 본다.** `--oracle-only` 없이 불렀는데 README 의 요구를 처리하는 코드(최적화, API 라우트, CLI 나 배치의 진입점)를 하나도 찾지 못하면 구현 전으로 보고 묻는다: 판정기만 쓰고 멈춤(`--oracle-only` 와 같음, 권장), 또는 그대로 진행. 물을 수 없으면 판정기만 쓰고 멈춘다. 구현 전에 판정기를 커밋해야 "판정기를 구현 전에 씀" 이 지켜지기 때문이다.
- `precheck` 는 흔한 설정 꼴만 본다. 시작 스크립트와 설정 로더가 읽는 곳(코드 안의 기본값, 다른 이름의 설정 파일, 프레임워크가 환경에서 덮어쓰는 이름)도 직접 읽어 확인한다.

### 1. 담당자 사실

- 담당자(사용자)가 준 업무 규칙, 수치 기준, 권한 규칙을 `docs/evidence/owner-facts.md` 에 옮긴다. 항목마다 출처(사용자 메시지 인용과 날짜, 또는 담당자가 준 문서의 경로)를 붙인다.
- 구현에서 읽은 것, 스스로 짐작한 것은 넣지 않는다. 담당자 사실이 없으면 묻는다. 그래도 없으면 `담당자 사실 없음` 한 줄로 두고 그 사실을 `verify.md` 에 적는다.
- 요구가 README 가 아닌 문서(사용자가 준 명세)에 있으면 그 경로를 `room` 의 `--req` 로 준다.

### 2. 판정기(구현 보기 전)

1. 방을 만든다: `node "$E" room [--req <요구 문서>]`. 출력의 `room: <폴더>` 가 방 `R` 이다.
2. 아래 지시문의 `{R}` 만 채워 `docs/evidence/logs/verify-oracle-prompt-{ts}.md` 에 그대로 저장하고, 그 글 그대로 하위 에이전트를 띄운다. 구현에서 알게 된 이름, 형식, 식, 경로를 더하지 않는다.

   ```text
   당신은 판정기(oracle) 작성자입니다. 작업 폴더는 {R} 입니다.
   - 읽어도 되는 파일은 {R} 안의 파일뿐입니다(요구 문서와 docs/evidence/owner-facts.md). {R} 밖의 경로는 읽지도, 목록을 보지도, 실행하지도 않습니다.
   - 쓸 곳은 {R}/tests/oracle/ 뿐입니다.
   - 만들 것:
     1. 판정기: 입력과 출력만 보고 세 가지를 판정합니다. 제약을 모두 지키는가(constraint), 보고된 목적값이 입력과 출력으로 다시 계산한 값과 같은가(objective), 권한 규칙을 지키는가(permission). 판정마다 한 줄 `ORACLE <constraint|objective|permission> <PASS|FAIL|ERROR> <사례 이름> [설명]` 을 표준 출력에 찍습니다. 사례 이름은 공백 없는 한 낱말입니다. 구현이 뜨지 않았거나, 응답이 없거나, 출력을 읽지 못해 판정할 수 없으면 FAIL 이 아니라 ERROR 를 찍습니다. 요구 문서와 담당자 사실에 권한 규칙이 없으면 permission 은 만들지 않고 그 사실을 RUN.md 에 적습니다.
     2. 판정기 자체 시험: 손으로 만든 입력과 출력(맞는 것과 틀린 것)으로 판정기만 시험합니다. 구현을 부르지 않습니다. RUN.md 에 자체 시험 명령도 한 줄 적습니다. 목적값 계산과 제약 판정 함수는 다른 스크립트가 불러 쓸 수 있게 내보내고, 그 이름을 RUN.md 에 적습니다.
     3. RUN.md: 판정기로 구현을 판정하는 명령 한 줄. 명령은 프로젝트 맨 위 폴더(요구 문서가 있는 폴더)에서 돕니다. 구현을 부르는 방법이 요구 문서에 있으면(실행 방법, API) 판정기가 그 폴더에서 구현을 직접 띄워 부르고 끝에 내립니다. 빈 포트를 쓰고, 이미 떠 있는 서버는 쓰지 않습니다. 방법이 없으면 IO.md 에 입력 파일과 출력 파일의 형식을 정해 그 파일을 읽게 합니다. 명령은 파일을 하나하나 이름으로 줍니다(폴더 인자는 판에 따라 시험을 하나도 돌리지 않습니다).
     4. REQUIREMENTS.md: 요구 문서의 요구를 빠짐없이 번호(R1, R2...), 요구 문서:줄, 원문 문장으로 적습니다.
   - 시험은 돌리지 않습니다. 끝에 읽은 파일 목록(명령으로 본 것 포함)과 만든 파일 목록을 보고합니다.
   ```

3. 띄울 수 없으면(이미 하위 에이전트 안, 다중 에이전트 기능이 꺼짐, 비대화 실행) 같은 맥락이 판정기를 쓰지 않는다. `verify.md` 는 `작성 안 함(하위 에이전트를 띄울 수 없음: <까닭>)` 으로 두고 끝 보고에 올린다.
4. 돌아오면 `node "$E" run --log 'docs/evidence/logs/verify-collect-{ts}.log' -- node "$E" collect --room <R>`. 거부되면(종료 1) 그 판정기를 버리고 새 방으로 다시 띄운다. 두 번 더 실패하면 멈추고 알린다. 보고된 읽은 파일 목록에 방 밖의 경로가 있어도 같다.
5. 판정기 자체 시험을 RUN.md 의 명령으로 `run` 해 로그를 남긴다(구현은 부르지 않으므로 HEAD 에서 돌려도 된다). 실패하면 판정기를 고치지 않고, 그 사실을 적은 뒤 새 방으로 다시 띄운다.
6. `verify.md` 의 "격리" 절에 적는다. 방은 읽을 파일을 줄일 뿐, 하위 에이전트가 방 밖을 읽지 못하게 막지는 않는다. 그 사실도 적는다.
   - 지시문 로그 경로
   - 하위 에이전트가 보고한 읽은 파일 목록. 자기 보고라는 사실도 적는다
   - 자동으로 들어갔을 수 있는 맥락: 세션 폴더(저장소)의 `CLAUDE.md`, `AGENTS.md`, 사용자 전역 지시 파일(`~/.claude/CLAUDE.md`, `~/.claude/rules/`, `~/.codex/AGENTS.md`), 자동 메모리, Claude Code 가 붙이는 git 상태(최근 커밋 제목). 그 가운데 구현 구조나 식을 설명하는 것이 있으면 그 사실을 한계로 적는다

### 3. 판정기 커밋

```bash
node "$E" commit --paths tests/oracle --paths docs/evidence/owner-facts.md --paths docs/evidence/logs --message "test(oracle): README 와 담당자 사실만으로 쓴 판정기"
```

- 구현 커밋보다 앞서는지 `git log --format='%h %ad %s' --date=iso -- tests/oracle <구현 경로>` 를 `run` 으로 남긴다.
- 담당자 사실, 지시문 로그, collect 로그가 판정기와 같은 커밋에 들어가, 판정기가 무엇을 보고 언제 쓰였는지 git 으로 보인다.
- 구현이 이미 있었으면 `verify.md` 첫 줄에 `요구 미충족: 판정기가 구현 뒤에 쓰임(<순서 로그>)` 을 쓰고 끝 보고에도 올린다. 순서를 꾸미지 않는다.
- `--oracle-only` 면 여기서 멈추고, 구현한 뒤 다시 부르라고 알린다.

### 4. optimize.md

| 항목 | 내용 |
|---|---|
| 목적 함수 | 최소화 또는 최대화하는 값과 식 |
| 제약 | 제약마다 한 줄. 강한 제약과 약한 제약(벌점)을 나눔 |
| 알고리즘 이름 | 쓴 알고리즘의 이름. 라이브러리면 이름과 판(잠금 파일이나 매니페스트에서 읽음, 그 경로를 적음) |
| 핵심 함수 | `파일:줄`. 목적값 계산, 제약 검사, 탐색 본체를 각각 |
| 의사코드 | 10줄. 코드 펜스(```) 안에 씀 |
| 실행 명령, 로그 | 줄 번호를 확인한 명령(예: `git grep -n "def objective"`)을 `run` 으로 남긴 로그 |

`파일:줄` 은 그 로그가 보인 줄만 쓴다. 로그 둘째 줄의 `head=` 가 확인한 커밋이다.

### 5. verify.md (판정 실행과 버그 셋)

1. **잇기**: RUN.md 가 IO.md 형식을 요구하면, 구현을 그 형식으로 잇는 어댑터 `docs/evidence/scripts/oracle-adapter.*` 를 쓴다. 어댑터는 구현을 부르고 형식만 바꾼다. 목적값이나 제약을 스스로 계산하지 않는다. 판정기 파일은 고치지 않는다.
2. **DB 격리**: 판정기는 구현을 띄워 요청을 보낸다. 버그를 넣은 구현이 쓰는 DB 는 일회용이어야 한다(작업 트리 안의 파일 DB, 임시 SQLite, 시험 전용 스키마나 컨테이너). 그렇게 돌리는 환경 변수를 RUN.md 명령 앞에 주고 `verify.md` 에 적는다. 일회용으로 돌릴 수 없으면 묻고, 허락이 없으면 `미검증(DB 격리 불가)` 이다.
3. **기준선**: 판정기는 HEAD 의 별도 작업 트리에서, 그 작업 트리의 구현을 직접 띄워 돈다. 이미 떠 있는 서버를 쓰면 넣은 버그가 반영되지 않는다. 빈 포트를 쓴다.
   ```bash
   wt=$(node "$E" worktree [--link <의존 폴더>])
   node "$E" bug --worktree "$wt" --name baseline -- <RUN.md 의 명령>
   ```
   - 구현이 추적되지 않는 의존 폴더(`node_modules`, `.venv`)를 쓰면 `--link` 로 이어 준다. 빌드 결과(`dist`, `build`, `target` 등)는 잇지 않는다. 버그를 넣은 빌드가 사용자 폴더에 써지기 때문이다. 빌드가 필요하면 RUN.md 명령 앞에서 작업 트리 안에 새로 빌드한다. 별도 작업 트리에 없는 것을 받으려고 설치하지 않는다.
   - 링크한 폴더가 원래 트리의 코드를 가리키면(작업 공간 패키지 링크, editable 설치) `bug` 가 `WARN` 과 `links_to_repo=` 를 찍고 결과를 `undecidable(link-to-main)` 으로 둔다. 넣은 버그 대신 사용자 코드가 돌기 때문이다. Python 은 링크 대신 `PYTHONPATH=<작업 트리>/src` 를 명령 앞에 줄 수 있다. 그래도 안 되면 버그 셋은 `미검증(의존 폴더가 원래 트리를 가리킴)` 이다.
   - 로그 끝의 `METRIC baseline.<종류>.pass=`, `fail=`, `error=` 이 지금 구현의 판정 결과다. 실패가 있으면 그것이 찾은 결함이다. 고치지 않고 적는다.
   - 기준선이 판정 줄을 하나도 내지 않았거나 ERROR 가 있으면 판정기나 RUN.md 명령이 구현을 부르지 못한 것이다. 버그 셋으로 가지 않고 그 로그를 적은 뒤, 명령(환경 변수, 포트, 빌드)을 고쳐 기준선을 다시 돈다. 판정기 파일은 고치지 않는다.
4. **버그 셋**: 종류마다 새 작업 트리를 만들고, 그 작업 트리의 구현 파일만 고친 뒤 돌린다. 사용자 작업 트리의 파일은 고치지 않는다.
   ```bash
   wt=$(node "$E" worktree [--link <의존 폴더>])
   # "$wt" 안의 구현 파일을 고침(예: 제약 검사를 건너뜀)
   node "$E" bug --worktree "$wt" --name constraint --kind constraint --baseline <기준선 로그> -- <RUN.md 의 명령>
   ```

   | 종류 `--kind` | 넣는 방법의 예 |
   |---|---|
   | `constraint` | 해를 고르는 단계나 검사에서 제약 하나를 빼서, 실제로 위반한 해가 나오게 함 |
   | `objective` | 목적값 합산에서 항 하나를 빼거나 부호를 바꿈 |
   | `permission` | 권한 확인을 늘 통과하게 바꿈 |

   - `bug` 가 남기는 것: 패치(`verify-bug-<이름>-*.patch`), 로그, 그리고 로그 끝의 `METRIC bug.<이름>.result=`, `reason=`, `collateral=`, `tree_unchanged=`, `links_unchanged=`.
   - `bug` 는 기준선이 지금 HEAD 와 지금 판정기의 것인지 본다. 아니면 거부하므로 기준선을 다시 돈다.
   - `caught`: 기준선과 같은 사례를 모두 판정했고 ERROR 가 없으며, 기준선에 없던 그 종류의 FAIL 이 나옴.
   - `missed`: 같은 조건에서 그 종류의 새 FAIL 이 없음.
   - `undecidable`: 시간 초과(`timeout`), ERROR 가 있음(`oracle-error`), 판정한 사례가 기준선과 다름(`cases-differ`, 충돌로 중간에 끝남), 기준선에 그 종류의 PASS 가 없음(`baseline-no-pass`, 잡을 수 없음), 링크가 원래 트리를 가리킴(`link-to-main`). 잡음으로 세지 않는다. 버그를 고쳐 넣어 다시 돌리고 두 로그를 다 적는다.
   - `collateral` 이 0 이 아니면(다른 종류에도 새 FAIL) 그 사실을 표에 적는다.
   - `missed` 면 그 버그가 판정기의 입력에서 실제로 출력을 바꾸는지 확인한다(같은 패치를 새 작업 트리에 `git apply` 해 구현이나 어댑터를 돌린 로그). 출력이 같으면 `버그가 출력을 바꾸지 않음` 으로 적고 다른 자리에 넣어 다시 돈다. 출력이 바뀌는데 놓쳤으면 판정기의 빈틈이다.
   - 판정기의 빈틈은 구현을 본 이 맥락이 고치지 않는다. 고치려면 새 방과 새 하위 에이전트에 요구 수준의 한 문장(넣은 버그나 구현 내용 없이)만 더해 다시 쓰게 하고, `collect --replace` 로 가져와 새 커밋으로 남긴다. 처음 결과 `missed` 는 지우지 않고, 고친 뒤 결과는 다른 열에 적는다. `verify.md` 에 처음 판정기 커밋과 바꾼 판정기 커밋, 각각이 구현보다 앞서는지를 따로 적는다.
   - 출력 비교 같은 확인용 작업 트리는 `bug --name probe-<이름>` 으로 돌리거나 `worktree --remove` 로 지운다.
   - `tree_unchanged=no` 나 `links_unchanged=no` 면 멈추고 사용자에게 알린다. 이 확인은 추적 파일의 내용, 추적되지 않는 파일, 링크한 폴더를 본다. 무시된 다른 파일과 DB 는 보지 못한다는 사실을 `verify.md` 에 적는다.
   - 권한 규칙이 요구 문서와 담당자 사실에 없으면 permission 행은 `해당 없음(권한 규칙 없음)` 이다.
5. 표에는 버그마다 패치 경로, 결과 `` `bug.<이름>.result=...` `` 와 `reason`, 로그 경로를 적는다.

### 6. flow.md

- 순서는 화면, API, 최적화, DB, 내보내기다. 단계마다 처리하는 `파일:줄` 을 적는다.
- **서버**: 떠 있지 않으면 `serve` 로 띄운다. 시작 스크립트가 마이그레이션, 시드, 초기화를 함께 하면 그 사실을 보이고 허락을 받은 뒤에만 띄운다. 이미 떠 있던 서버는 내리지 않고, 띄운 서버는 끝에 `stop` 으로 내린다.
  ```bash
  node "$E" serve --log 'docs/evidence/logs/flow-server-{ts}.log' --pid <임시폴더>/server.pid --ready http://{host}:{port}/ -- <시작 명령>
  ```
- **종단 시험**: 스크립트 `docs/evidence/scripts/e2e-flow.*` 가 다섯 단계를 실제 요청으로 지나며 단계마다 METRIC 줄을 찍는다(예: `flow.api.status=200`, `flow.api.ms=`, `flow.db.rows=`, `flow.export.bytes=`). `run --timeout 300` 으로 돌린다.
  - 화면 단계: 이미 설치된 브라우저 도구가 있으면 실제로 누르고, 없으면 화면 URL 의 응답과 화면이 부르는 API 요청을 보낸다. 어느 쪽인지 적고, HTTP 로 대신했으면 `trace.md` 의 화면 요구는 `부분(화면 조작 미검증)` 이다.
  - DB 확인은 읽기(SELECT)만 하고 로컬이나 일회용 DB 에서만 한다. 시험이 만든 행은 표식을 달고, 끝에 지우거나 남긴 사실을 적는다. 서버가 사용자 폴더에 파일 DB 를 새로 만들었으면 그 경로와 남긴 사실도 적는다.
  - 로그에는 시험이 만든 행만 찍는다.
- 서버에 닿지 못하면 종단 시험 칸은 `미검증` 과 오류 문구다. 단위 시험으로 대신하지 않는다.

### 7. scale.md

- **배수 데이터**: `docs/evidence/scripts/gen-scale.*` 가 기준 데이터(README 의 예시나 시험 고정물)를 1배, 5배, 10배로 늘린다. 시드를 고정해 적는다. 기준 데이터가 작아 10배도 요구의 상한에 못 미치면 상한 근처 사례를 하나 더 만들고 그 사실을 적는다. 기준 데이터가 없으면 `미검증(기준 데이터 없음)`.
- **측정**: `docs/evidence/scripts/measure.*` 가 배수마다 최적화를 3회 돌려 각 시간과 중앙값, 목적값을 METRIC 줄로 찍는다(예: `scale.x5.median_s=`, `scale.x5.objective=`). 무엇을 쟀는지(함수 호출만, HTTP 포함) 적는다. 시간 제한은 실행 전에 정해 문서와 `run --timeout` 에 같게 준다. 걸리면 `시간 초과(제한 N초)` 다. 배수마다 판정기의 제약 판정을 돌려 `scale.x5.feasible=` 을 찍는다.
- **완전 탐색**: 작은 사례 다섯을 `docs/evidence/scripts/brute-force.*` 로 푼다. 목적값과 실행 가능성은 `tests/oracle/` 의 판정기가 내보낸 함수로 계산하고 구현 코드를 부르지 않는다. 판정기가 그런 함수를 내보내지 않으면 완전 탐색 스크립트가 요구 문서와 담당자 사실만으로 직접 계산하고, 그 사실을 적는다. 크기는 완전 탐색이 제한 안에 끝나는 가장 큰 쪽으로 한다.
  - 사례마다 구현의 목적값, 정해, 차이를 스크립트가 찍는다. 차이(%)는 부호를 지킨다: `(구현 - 정해) / |정해| x 100`. 정해가 0 이면 두 값만 찍는다.
  - 구현이 정해보다 좋으면(최대화에서 크거나 최소화에서 작으면) `gap.c<n>.flag=better-than-optimal` 을 찍고, 제약 위반이나 완전 탐색 오류로 보고 조사한다.

### 8. decisions.md

| 결정 | 고른 것 | 버린 것 | 이유 | 출처 | 확인하는 시험 | 결과 로그 |
|---|---|---|---|---|---|---|

- 출처는 코드, 커밋 메시지, README, ADR, 이 세션의 대화(날짜) 가운데 실제로 그렇게 말한 곳이다.
- 출처가 말하지 않는 "버린 것" 과 "이유" 는 `기록 없음` 이다. 지어내지 않는다.
- 확인하는 시험은 실제로 있는 시험 이름이다. 결과는 통과와 실패 그대로다. 없으면 `없음`.

### 9. trace.md

| 번호 | 요구 | 출처 | 상태 | 시험 이름 | 로그 경로 |
|---|---|---|---|---|---|

- 요구 뽑기: 요구 문서의 요구 절의 목록 항목 전부와 "해야", "한다", "must", "should" 가 든 문장 전부다. 한 문장의 나열은 항목마다 한 행이다. 출처는 `README.md:<줄>` 이다. 요구 칸은 원문을 줄이지 않고 큰따옴표 안에 옮긴다(`|` 는 `\|`). 나열을 나눈 행은 원문 전체를 옮기고 그 행이 맡은 항목을 뒤에 적는다.
- 판정기 작성자의 `tests/oracle/REQUIREMENTS.md` 와 대조해 한쪽에만 있는 요구를 표 아래에 적는다.
- 담당자 사실은 요구 문서의 요구가 아니므로 행으로 넣지 않는다. 판정기가 담당자 사실을 판정한 결과는 `verify.md` 에 있다.
- 상태는 넷 가운데 하나다.
  - `완료`: 그 요구를 확인하는 시험이 있고 통과함. 건너뜀이나 0개 실행은 통과가 아니다
  - `부분`: 일부만 구현, 시험이 일부만 확인, 시험이 실패, 시험이 없음. 빠진 것을 적음
  - `미구현`: 이유를 적음
  - `미검증`: 시험을 돌릴 수 없었음(서버, 도구, 샌드박스). 까닭을 적음
- 개수는 손으로 세지 않는다: `node "$E" run --log 'docs/evidence/logs/trace-count-{ts}.log' -- node "$E" count --doc docs/evidence/trace.md`. 그 METRIC 값을 표 아래에 옮긴다. 종료 1(상태를 알 수 없는 행)이면 표를 고치고 다시 센다.

### 10. 수치 대조

```bash
node "$E" run --log 'docs/evidence/logs/check-{ts}.log' -- node "$E" check
```

- `ERROR` 는 모두 고친다. 로그에 없는 수는 지우거나 그 수를 찍는 명령을 다시 돌린다.
- `WARN`(`이름=값` 밖의 숫자)도 0 이 될 때까지 고친다. 측정값이면 METRIC 으로 바꾼다. 측정값이 아니면 도우미가 빼는 꼴로 쓴다: 코드 펜스나 백틱 안, URL, `/`, `./`, `~/` 로 시작하는 경로와 확장자로 끝나는 경로, 확장자가 있는 `파일:줄`, 글자가 든 해시, 날짜, 판, `R1`, `c3` 같은 번호, 배수 데이터 이름(`5배 데이터`처럼 뒤에 데이터나 입력이 오거나 표 행의 첫 칸에 홀로 있을 때, 또는 `x5`), `10줄`, `3단계`, 끝에 점이 있는 절 번호(`## 5. `)와 목록 번호, 세 자리 이하의 표 행 번호. 큰따옴표 안의 인용은 `trace.md` 의 요구 칸에서만 빠진다. 제목 줄의 다른 수, `시간도 10배` 나 표의 `약 5배` 같은 비율, `120ms`, `p50/p95=120/340ms`, `1200req/s` 같은 수는 측정값이므로 METRIC 으로 바꾼다.
- 문서마다 마지막 줄은 `수치 대조: <check 로그 경로>` 한 줄이다(이 꼴의 줄만 대조에서 빠짐). `{ts}` 같은 이름 꼴이 아니라 실제 로그를 가리켜야 한다. 마지막 대조의 로그 이름을 먼저 정해(예: `docs/evidence/logs/check-final-20261105-0930.log`) 문서에 쓰고, 그 이름 그대로 `run --log` 로 check 를 돌린다. `run` 이 로그 머리를 먼저 쓰므로 check 가 그 로그를 찾는다. 그 대조가 실패하면 고친 뒤 새 이름으로 다시 한다.

### 11. 커밋

```bash
node "$E" commit --message "docs(evidence): 증거 문서 여섯"
node "$E" check --tracked
```

- `ERROR 비밀값 꼴이 남음` 이면 값을 가린다. 비밀값이 아니라고 사용자가 확인한 자리만 `--accept <파일:줄>` 로 넘긴다.
- 커밋 훅이 막으면 우회하지 않고 알린다.
- 커밋 뒤 `check --tracked` 로 문서가 가리킨 로그가 모두 커밋에 들었는지 본다.
- push 하지 않는다. 사용자가 요청할 때만 한다.

## 보고

| 문서 | 상태 | 미검증이나 미구현 | 핵심 결과 |
|---|---|---|---|

- 상태는 `작성`, `일부 미검증`, `작성 안 함(까닭)` 가운데 하나다.
- 핵심 결과에는 판정기 기준선의 실패 수, 버그 셋의 결과와 까닭, trace 의 상태별 개수, 수치 대조의 오류와 경고 수를 METRIC 값 그대로 적는다.
- `요구 미충족`(판정기가 구현 뒤에 쓰임), 찾은 결함, 띄운 서버를 내렸는지, 커밋 해시를 적는다. push 는 하지 않았다고 적는다.
- `요구 미충족` 이면 마지막 줄에 다음 행동을 적는다: 다음 프로젝트는 구현을 시작하기 전에 `/banker:make-evidence --oracle-only`(Codex 는 `$banker-make-evidence --oracle-only`, 플러그인 설치면 `$banker:make-evidence --oracle-only`)로 판정기를 먼저 커밋한다.
- `--oracle-only` 로 멈췄으면 마지막 줄에 다음 행동을 적는다: 구현을 마친 뒤 같은 스킬을 인자 없이 다시 부른다.
