# make-evidence: 실행으로 만드는 증거 문서 여섯

구현한 서비스가 README 의 요구를 지키는지, 실제로 실행한 결과로 보이는 문서 여섯을 만든다.
문서는 `docs/evidence/` 에 쓰고 커밋한다. 답변은 한글.

## 원칙

- **수치는 손으로 쓰지 않는다.** 시간, 목적값, 차이(%), 통과 수, 건수는 실행 로그에서만 옮긴다. 로그에 없는 수는 문서에 쓰지 않는다.
- **문서마다 실행 명령과 로그 경로를 적는다.** 읽는 사람이 같은 명령을 다시 돌려 같은 로그를 얻을 수 있어야 한다.
- **실행하지 못한 것은 실행하지 못했다고 쓴다.** 서버가 안 뜨거나 도구가 없으면 그 칸은 `미검증` 과 까닭이다. 추정값이나 예상값으로 채우지 않는다.
- **미구현을 숨기지 않는다.** README 요구 가운데 구현하지 않은 것은 `trace.md` 에 `미구현` 과 이유로 남긴다.
- 문서에 비밀값을 넣지 않는다. 로그에 토큰, 비밀번호, 키가 찍혔으면 커밋 전에 값을 `***` 로 가리고, 가렸다는 사실을 그 문서에 적는다.

## 인자

- `--host <host>`, `--port <port>`: `flow.md` 의 종단 시험이 요청을 보낼 서버. 없으면 README, `.env.example`, 서비스 시작 스크립트에서 찾고, 그래도 없으면 사용자에게 묻는다. 찾은 값과 그 출처를 `flow.md` 에 적는다.
- `--only <문서,...>`: 일부만 만든다(예: `--only scale,trace`). 이름은 `optimize`, `verify`, `flow`, `scale`, `decisions`, `trace`.
- `--no-commit`: 파일만 쓰고 커밋하지 않는다.

## 폴더

```
docs/evidence/
  optimize.md  verify.md  flow.md  scale.md  decisions.md  trace.md
  logs/        실행 로그. 문서는 이 파일들을 경로로 가리킨다
  scripts/     데이터 생성, 측정, 완전 탐색처럼 증거를 만드는 데 쓴 스크립트
tests/oracle/  판정기와 그 시험 (verify.md)
```

- 로그 이름은 `<문서>-<무엇>-<YYYYMMDD-HHMMSS>.log` 다. 같은 시험을 다시 돌리면 새 파일을 만들고, 문서는 마지막 로그를 가리킨다.
- 로그는 명령의 표준 출력과 표준 오류를 함께 담고, 첫 줄에 실행한 명령, 마지막 줄에 종료 코드를 남긴다.

```bash
run_log() {  # run_log <로그 경로> <명령...>
  mkdir -p "$(dirname "$1")"; f=$1; shift
  { echo "\$ $*"; "$@"; echo "exit=$?"; } > "$f" 2>&1
}
```

## 진행

먼저 저장소를 읽는다: README, 시작 스크립트, 시험 실행 방법, 최적화 코드, DB 스키마, 내보내기 코드.
문서 여섯은 아래 순서로 만든다. `verify.md` 의 판정기는 다른 문서보다 먼저 쓴다.

### 1. optimize.md

| 항목 | 내용 |
|---|---|
| 목적 함수 | 최소화 또는 최대화하는 값과 식 |
| 제약 | 제약마다 한 줄. 강한 제약과 약한 제약(벌점)을 나눔 |
| 알고리즘 이름 | 쓴 알고리즘의 이름(예: 정수 계획법, 담금질, 탐욕 + 지역 탐색). 라이브러리를 쓰면 그 이름과 판 |
| 핵심 함수 | `파일:줄` 로. 목적값 계산, 제약 검사, 탐색 본체를 각각 |
| 의사코드 | 10줄 |

- `파일:줄` 은 지금 커밋에서 실제로 그 줄을 열어 확인한 것만 쓴다. 문서 끝에 확인한 커밋 해시를 적는다.
- 이 문서에는 실행 수치가 없다. 실행 명령 칸에는 줄 번호를 확인한 명령(예: `grep -n 'def objective' src/opt.py`)과 그 출력 로그를 적는다.

### 2. verify.md

판정기(oracle)는 구현을 보지 않은 하위 에이전트가 쓴다. 구현을 본 맥락이 판정기를 쓰면 구현의 실수를 판정기도 따라 한다.

1. **담당자 사실을 모은다.** 담당자(사용자)가 준 업무 규칙, 수치 기준, 권한 규칙을 `docs/evidence/owner-facts.md` 에 그대로 옮긴다. 담당자 사실이 없으면 사용자에게 묻는다. 그래도 없으면 README 만으로 진행하고 그 사실을 `verify.md` 에 적는다.
2. **새 맥락 하위 에이전트를 띄운다.** 이 대화를 넘기지 않는다.
   - Claude Code: Agent 도구를 `general-purpose` 로, `model` 없이 부른다.
   - Codex: `spawn_agent` 를 `agent_type` 과 `model` 없이 부르고 대화를 넘기지 않는다(multi-agent v2 는 `fork_turns="none"`, v1 은 `fork_context` 를 주지 않음).
   - 지시에 들어갈 것:
     - 읽어도 되는 것은 `README.md` 와 `docs/evidence/owner-facts.md` 둘뿐이다.
     - 구현 폴더와 기존 시험은 열지 않는다.
     - 쓸 곳은 `tests/oracle/` 다.
     - 판정기는 입력과 출력만 보고 세 가지를 판정한다.
       - 제약을 모두 지키는가
       - 보고된 목적값이 입력과 출력으로 다시 계산한 값과 같은가
       - 권한 규칙을 지키는가
     - 시험은 판정기를 쓴다.
     - 끝에 읽은 파일 목록을 보고한다.
3. **읽은 파일 목록을 확인한다.** 목록에 두 파일 밖의 경로가 있으면 그 판정기는 버리고 다시 띄운다. 목록은 `verify.md` 에 옮긴다.
4. **판정기를 구현보다 먼저 커밋한다.** 커밋 메시지는 `test(oracle): ...` 다. 구현이 아직 없으면 이 커밋이 구현 커밋보다 앞선다. 구현이 이미 있으면 그 사실과 두 커밋의 순서(`git log --format='%h %ad %s' --date=iso -- tests/oracle <구현 경로>`)를 그대로 적는다. 순서를 꾸미지 않는다.
5. **판정기를 지금 구현에 돌린다.** 명령과 로그 경로, 통과와 실패 수를 로그에서 옮긴다.
6. **일부러 넣은 버그 셋을 판정기가 잡는지 본다.**

   | 버그 | 넣는 방법의 예 |
   |---|---|
   | 제약 위반 | 제약 검사 한 줄을 건너뛰게 바꿈 |
   | 목적값 오계산 | 목적값 합산에서 항 하나를 빼거나 부호를 바꿈 |
   | 권한 우회 | 권한 확인을 늘 통과하게 바꿈 |

   - 버그마다 차례로 진행한다.
     1. 바꾼 것을 패치 파일로 남긴다: `docs/evidence/logs/verify-bug-<이름>.patch`
     2. `git apply` 로 넣는다.
     3. 판정기를 돌려 로그를 남긴다.
     4. `git apply -R` 로 되돌린다.
     5. `git status --short` 와 `git diff --stat` 이 빈 것을 로그로 남긴다.
   - 표에는 버그마다 다섯 가지를 적는다: 패치 경로, 넣은 뒤 결과(잡음 또는 놓침), 로그 경로, 되돌린 명령, 되돌린 뒤 판정기 결과.
   - 놓친 버그는 놓쳤다고 쓰고, 판정기의 빈틈을 한 줄로 적는다. 놓친 것을 잡게 하려고 판정기를 고치면 그 커밋과 재실행 로그를 더한다.
   - 되돌리기가 실패하면 멈추고 사용자에게 알린다. 작업 트리를 지우거나 덮어쓰지 않는다.

### 3. flow.md

- 순서는 화면, API, 최적화, DB, 내보내기다.
- 단계마다 그 단계를 처리하는 `파일:줄` 을 적는다. 화면은 요청을 보내는 코드, API 는 라우트와 처리 함수, 최적화는 호출 지점, DB 는 쓰기와 읽기 쿼리, 내보내기는 파일을 만드는 함수다.
- **종단 시험**: `{host}:{port}` 에 떠 있는 서버에 실제 요청을 보내 다섯 단계를 끝까지 지난다.
  - 스크립트는 `docs/evidence/scripts/e2e-flow.*` 다.
  - 서버가 떠 있지 않으면 저장소의 시작 방법으로 띄운다. 띄운 명령과 그 로그를 적는다.
  - 화면 단계는 브라우저 도구(Playwright 등)가 있으면 실제로 누르고, 없으면 화면 URL 의 응답과 화면이 부르는 API 요청을 그대로 보낸다. 어느 쪽인지 적는다.
  - 단계마다 다섯 가지를 로그에 남긴다: 요청, 응답 코드, 걸린 시간, DB 에 생긴 행의 확인 쿼리 결과, 내보낸 파일의 이름과 크기.
- 서버에 닿지 못하면 종단 시험 칸은 `미검증` 과 오류 문구다. 단위 시험으로 대신하지 않는다.
- 운영 서버나 남의 서버에는 보내지 않는다. 대상이 로컬이나 개발 서버가 아니면 사용자에게 먼저 확인한다.

### 4. scale.md

- **데이터 1배, 5배, 10배**: 기준 데이터(README 의 예시나 시험 고정물)를 늘리는 스크립트 `docs/evidence/scripts/gen-scale.*` 로 만든다. 같은 시드로 다시 만들 수 있게 시드를 고정하고 적는다.
- 배수마다 최적화를 돌려 걸린 시간과 목적값을 잰다. 한 배수를 3회 돌려 각 값과 중앙값을 로그에 남긴다.
- **작은 사례 다섯**: 완전 탐색이 끝나는 크기로 다섯 개를 만들고, 완전 탐색 스크립트 `docs/evidence/scripts/brute-force.*` 로 정해를 구한다.
  - 사례마다 구현의 목적값과 정해를 적는다.
  - 차이(%)는 `|구현 - 정해| / |정해| x 100` 이다. 정해가 0 이면 차이 대신 두 값을 그대로 적는다.
  - 차이도 스크립트가 계산해 로그에 찍는다.
- 표의 칸마다 로그 경로를 단다. 시간 제한에 걸린 배수는 `시간 초과(제한 N초)` 로 적는다.

### 5. decisions.md

결정마다 한 행이다.

| 결정 | 고른 것 | 버린 것 | 이유 | 확인하는 시험 |
|---|---|---|---|---|

- 결정은 코드와 커밋 기록, README, ADR 이 있으면 ADR 에서 찾는다. 찾은 곳을 적는다.
- 확인하는 시험은 실제로 있는 시험의 이름이다. 이름마다 통과 로그 경로를 단다. 그 결정을 확인하는 시험이 없으면 `없음` 으로 적는다. 이름을 지어내지 않는다.

### 6. trace.md

README 의 요구마다 한 행이다.

| 번호 | 요구 | 상태 | 시험 이름 | 로그 경로 |
|---|---|---|---|---|

- 번호는 README 에 나온 순서로 `R1`, `R2` 다. 요구 칸에는 README 문장을 줄이지 않고 옮긴다.
- 상태는 셋 가운데 하나다.
  - `완료`: 그 요구를 확인하는 시험이 있고 통과함
  - `부분`: 일부만 구현했거나 시험이 일부만 확인함. 빠진 부분을 적음
  - `미구현`: 이유를 적음
- 시험이 실패하면 `완료` 로 쓰지 않는다. 시험이 없으면 `완료` 가 아니라 `부분` 이고, 시험이 없다고 적는다.
- 마지막에 상태별 개수를 적는다. 개수도 표에서 센 것이다.

## 수치 대조

문서를 다 쓴 뒤, 문서에 적은 수마다 그 칸이 가리키는 로그에 같은 수가 있는지 확인한다.

- 문서의 숫자(시간, 목적값, 차이, 개수)를 하나씩 뽑아 가리킨 로그에서 찾는다(`grep -F`).
- 로그에서 찾지 못한 수는 지우거나, 그 수를 찍는 명령을 다시 돌려 로그를 만든다.
- 대조 결과(확인한 수의 개수, 못 찾은 수)를 각 문서 끝의 `수치 대조` 줄에 적는다.

## 커밋

- 커밋 대상은 `docs/evidence/` 와 `tests/oracle/` 뿐이다. 다른 경로는 넣지 않는다.
  - 증거를 만들다 구현을 고쳤다면 그 수정은 따로 커밋하고 사용자에게 알린다.
  - 판정기 커밋은 2번의 4단계에서 이미 했다.
- 커밋 전에 비밀값을 찾는다. 걸린 값은 가린다. 커밋 메시지는 `docs(evidence): ...` 다.
- push 하지 않는다. 사용자가 요청할 때만 한다.
- `--no-commit` 이면 쓸 파일 목록만 보이고 커밋하지 않는다.

## 런타임

- Claude Code: `/banker:make-evidence`. 하위 에이전트는 Agent 도구다.
- Codex: npm 길 `$banker-make-evidence`, 플러그인 길 `$banker:make-evidence`. 하위 에이전트는 `spawn_agent` 다.
  - 기본 샌드박스가 `.git` 쓰기를 막으면 커밋 명령에 `sandbox_permissions: "require_escalated"` 를 청한다.
  - 로컬이 아닌 서버에 보내는 종단 시험은 네트워크 승인이 필요하다.
