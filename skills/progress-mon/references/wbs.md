# wbs.json (WBS 탭)

WBS 탭의 자료. 작업 분해와 일정을 간트 차트 한 장으로 보인다.
init 절차의 WBS 단계와 갱신 규칙(SKILL.md)에서 에이전트가 쓰고, `check` 가 wbs-gen 과 같은 검사로 확인한다.
화면은 자동 갱신하지 않는다. 주소 `?tab=wbs`, `export`, `static` 파일의 `#wbs`.

## 형식

wbs-gen 스킬의 계획 파일(`plan.json`)과 같은 형식이다. 같은 파일을 wbs-gen 에 넘기면 같은 격자의 XLSX 와 HTML 이 나온다.
날짜는 `wg-dates.mjs`, 검사와 배치는 `wg-plan.mjs`, 격자는 `wg-html.mjs` 가 한다. 이 스킬의 `scripts/` 에 있는 이 세 파일은 wbs-gen 정본의 사본이다(고치지 않는다).

```json
{
  "title": "<제목>",
  "subtitle": "<메모>",
  "start": "2026-10-19",
  "end": "2026-11-06",
  "holidays": "없음",
  "gates": [{ "date": "10/26", "label": "<게이트 이름>" }],
  "parts": { "app": { "name": "<파트 이름>", "light": "D6EAF8", "dark": "5DADE2" } },
  "rows": [
    { "kind": "group", "wbs": "1", "task": "<묶음>", "owner": "<팀>", "part": "app" },
    { "kind": "task", "wbs": "1.1", "task": "<작업>", "owner": "<담당>", "priority": "필수", "pending": "<기다리는 것>", "start": "10/19", "end": "10/23", "part": "app" },
    { "kind": "constraint", "wbs": "C-1", "task": "<외부 선행>", "owner": "<부서>", "date": "10/26" },
    { "kind": "milestone", "wbs": "M1", "task": "<마일스톤>", "date": "11/06" }
  ],
  "notes": [{ "heading": "[가정·변경]", "lines": ["<가정한 날짜와 까닭>"] }]
}
```

| 칸 | 뜻 |
|---|---|
| `title`, `subtitle` | 제목 줄. 기간과 영업일 수(시간 단위는 시간 수)가 함께 들어감 |
| `start`, `end` | 기간. `YYYY-MM-DD` 나 `YYYY-MM-DD HH:MM` |
| `holidays` | 공휴일. `"8/17, 10/5"` 같은 글이나 배열. 없으면 `"없음"` |
| `gates` | `[{ "date", "label" }]`. 그 날짜(시각) 열 왼쪽에 빨간 수직선 |
| `parts` | 파트 색. `light` 는 묶음 행 바탕, `dark` 는 막대. 6자리 16진수 |
| `bars` | 우선순위별 막대 색. 파트 색보다 앞섬 |
| `rows` | `kind` 가 `group`, `task`, `constraint`, `milestone` 인 행 |
| `legend`, `notes`, `sheet` | 범례 항목, 아래 메모, 시트 이름(XLSX 용) |

- 날짜는 `YYYY-MM-DD` 나 `M/D` 다. `M/D` 는 기간 안의 해로 읽는다
- 날짜를 받는 칸(`start`, `end`, 행의 `start`, `end`, `date`, `gates` 의 `date`)은 시각을 붙여도 된다: `YYYY-MM-DDTHH:MM`, `YYYY-MM-DD HH:MM`, `M/D HH:MM`. `24:00` 은 그날 끝(다음 날 00:00 과 같음)
- 시각은 아래 "시간대" 대로 현지 벽시계 값이다. 시간대(`Z`, `+09:00`)와 초는 받지 않는다(FAIL 줄이 그 까닭을 알림)
- 칸마다 자세한 뜻은 wbs-gen SKILL.md 의 "계획 파일(plan.json)" 절과 같다

## 단위

| 기간 | 단위 | 열 |
|---|---|---|
| 시작일과 종료일이 하루 이내(달력 날짜 2일 이내) | 시간 | 기간의 모든 시간. 주말, 공휴일, 밤도 열이 된다. 최대 48열 |
| 그보다 김 | 영업일 | 토, 일과 공휴일을 뺀 날. 주 머리글(`W1`) |

시간 단위의 규칙

- 칸 하나는 `H:00` 부터 `H+1:00` 앞까지. 머리글은 `11:00` 이고, 그 위 줄은 날짜(`11/25(수)`)
- 기간의 시작 시각은 그 시간으로 내리고 종료 시각은 다음 시간으로 올린다. 날짜만 쓴 `start` 는 00:00, `end` 는 그날 24:00
- 작업 `11:00`~`13:00` 은 11시, 12시 두 칸이다. 날짜만 쓴 시작과 종료는 그날 전체(기간 안)
- 시작 시각만 있고 종료가 없으면(`end` 가 없거나 `null`) 그 시각이 든 시간 끝까지. 종료가 시작보다 앞서거나 같으면 그 행이 FAIL
- 마일스톤, 게이트, `start` 와 `end` 없이 `date` 만 쓴 제약은 점이다. 시각이 있으면 그 시간 칸, 날짜만 있으면 그날 첫 칸(첫날이면 기간 시작 칸). 제약의 시작, 종료 칸은 그 점, 시간 칸 값은 1
- 점의 시각이 기간 끝과 같으면(기간 끝 18:00 에 서비스 오픈) 마지막 칸에 둔다
- 시작, 종료 칸은 계획에 적은 시각 그대로 보인다(`15:30`). 날짜만 쓴 값은 `00:00`, `24:00` 이나 기간 경계. 막대는 그 시각이 든 칸을 모두 칠하고, 시간 칸 값은 칠한 칸 수다(13:00~15:30 은 3)
- 마지막 머리 칸은 `시간`, 제목은 `N 시간` 이다
- 공휴일은 쓰지 않는다. `holidays` 가 있으면 WARN 한 줄

영업일 단위는 시각을 버리고 날짜만 읽는다. 기간을 바꿔 단위가 바뀌어도 같은 파일을 쓸 수 있다. 그래서 영업일 단위의 `end` 가 `2026-11-27 00:00` 이면 11/27 전체가 열이 된다. 그날을 빼려면 `2026-11-26` 으로 적는다.

## 시간대

`wbs.json` 의 시각은 시간대가 없는 벽시계 값이다. 프로젝트의 현지 시간대(사용자의 시간대. 진척도 화면이 시각을 보이는 시간대와 같음)로 적는다.

- `items.json` 의 시각(`t`, `s`)은 `Z` 가 붙은 UTC 다. 현지 시간대로 환산한 뒤 초와 `Z` 를 뗀다
- 커밋 `%cI` 는 커밋한 PC 의 시차(`+09:00`)가 붙는다. 시차가 프로젝트 시간대와 다르면 환산하고, 같으면 초와 시차만 뗀다
- `events.jsonl` 의 시각도 시간대를 보고 같게 환산한다
- `Z` 나 시차를 떼기만 하지 않는다. 9시간 어긋나고, 날짜와 단위(2일 이내 판정), 주말 판정까지 바뀔 수 있다

| 기록 | 프로젝트 시간대 | `wbs.json` 에 적을 값 |
|---|---|---|
| `items.json` 의 `2026-11-25T01:00:00Z` | KST(+09:00) | `2026-11-25 10:00` |
| `items.json` 의 `2026-11-24T20:30:00Z` | KST(+09:00) | `2026-11-25 05:30`(날짜가 바뀜) |
| 커밋 `%cI` 의 `2026-11-25T10:00:00+09:00` | KST(+09:00) | `2026-11-25 10:00` |
| 커밋 `%cI` 의 `2026-11-24T17:00:00-08:00` | KST(+09:00) | `2026-11-25 10:00` |

## 날짜를 어디서 얻나

아래 순서로 찾는다. 찾은 날짜만 적는다.

1. `config.json` 의 `stories`, `stages` 와 진척도 기록. `items.json` 의 스토리와 단계 상태 기록 시각, 기타 항목의 시작과 완료 시각
2. `.omc/plans/*.md`(Codex `.omx/plans/`)의 일정, 마감, 단계 계획
3. ultra-chain 실행 기록(`events.jsonl`)의 단계 시작, 끝 시각
4. 커밋 기록(`git log`)의 커밋 시각(`--format="%h %cI %s"` 의 `%cI`). 스토리 완료 커밋이 그 작업의 실제 종료

- 날짜를 지어내지 않는다. 근거가 없는 작업은 행을 두되 `pending` 칸에 기다리는 것(예 `범위 확정`)을 적고, 날짜를 가정했으면 `notes` 의 `[가정·변경]` 에 그 날짜와 까닭을 적는다
- 날짜가 하나도 없으면 `wbs.json` 을 쓰지 않는다. 화면은 "자료 없음" 이고, 보고에 까닭을 적는다
- 끝난 작업은 실제 시작과 끝(기록과 커밋 시각을 현지로 환산)으로, 남은 작업은 계획 날짜로 적는다
- 날짜가 하나도 없으면 `config.json` 에 `"wbsAsk": false` 를 적어 인자 없는 호출이 WBS 단계를 다시 묻지 않게 한다(`references/config.md`)

## 주말과 공휴일

영업일 단위는 토, 일과 공휴일이 열에 없다. 시작, 종료, 마일스톤, 게이트가 그런 날이면 FAIL 이다. 실제 날짜가 주말이나 공휴일이면 아래처럼 적는다. 날짜를 말없이 옮기지 않고, 이 FAIL 로 `wbs.json` 을 지우지 않는다.

| 경우 | 적는 법 |
|---|---|
| 작업이 주말에 시작하거나 끝남 | 그 작업이 걸친 영업일로 적는다. 시작은 다음 영업일, 종료는 앞 영업일. `notes` 의 `[가정·변경]` 에 실제 날짜를 적는다(예 `1.2 실제 11/21(토)~11/24(화)`) |
| 마일스톤, 게이트가 주말 | 앞 영업일에 두고 `[가정·변경]` 에 실제 날짜를 적는다 |
| 작업이 영업일에 하나도 걸치지 않음(토요일 하루 작업 등) | 행으로 그리지 않는다. `notes` 의 `[주말·공휴일 작업]` 에 WBS 번호, 이름, 실제 날짜(시각)를 적는다 |

- 기간이 2일 이내면 시간 단위라 주말과 공휴일도 열이 된다. 이 규칙은 영업일 단위에만 쓴다
- check 의 `주말이나 공휴일` FAIL 줄 끝에 이 절을 가리키는 안내가 붙는다

## 공휴일

이 스킬은 내려받지 않는다(망분리에서도 같게 동작).

- 계획과 문서에 적힌 공휴일, 사용자가 알려 준 공휴일만 `holidays` 에 적는다
- 없으면 `"없음"` 으로 두고 보고에 `공휴일 미확인` 을 적는다
- 공휴일 목록을 받아야 하면 wbs-gen 의 `holidays` 명령(인터넷 필요)을 사용자에게 안내한다

## 검사

`check` 가 wbs-gen 의 `check` 와 같은 규칙으로 본다.

| 줄 | 뜻 |
|---|---|
| `FAIL wbs.json $ JSON 아님: ...` | JSON 이 아님 |
| `FAIL wbs.json rows[3] 1.1 시작: 주말이나 공휴일 (...). 실제 날짜면 ...` | 행 오류. json 경로 뒤가 WBS 번호와 칸. 주말, 공휴일이면 위 "주말과 공휴일" |
| `FAIL wbs.json rows[3] 1.1 시작: 날짜로 읽지 못함 (...). 시간대(Z, +09:00)와 초는 쓰지 않음...` | UTC 나 시차가 붙은 시각을 그대로 옮김. 위 "시간대" 대로 환산 |
| `FAIL wbs.json gates[0] ...` | 게이트 날짜 오류 |
| `FAIL wbs.json $ ...` | 기간, 제목 같은 계획 전체 오류 |
| `WARN wbs.json $ ...` | 기간 밖 공휴일, 시간 단위의 공휴일 |
| `WARN density wbs 작업 0/1`, `WARN density wbs 담당 n/m: <WBS 번호>` | 밀도(init 기록과 `wbs.json` 이 있을 때). 날짜를 만들어 채우지 않는다. 날짜 근거가 없는 작업은 `pending`, `notes` 에 둔다 |

- FAIL 이 3회 고친 뒤에도 남으면 `wbs.json` 만 지워 "자료 없음" 으로 두고 `config.json` 에 `"wbsAsk": false` 를 적는다(SKILL.md init 절차의 정리 단계). `주말이나 공휴일` FAIL 은 지우지 않고 위 규칙으로 고친다
- 화면은 오류가 있으면 격자 대신 오류 줄(앞 20개)을 보인다

## 갱신

- 일정이 바뀌거나 단계, 스토리가 시작하거나 끝나면 `wbs.json` 을 고치고 `check` 를 돌린다
- 실제 시작, 끝 시각은 `stage`, `story`, `item` 기록과 커밋에서 옮기되 현지 시간대로 환산한다
