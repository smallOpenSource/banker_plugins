# arch.json

구성도 탭의 영역(zones), 구성요소(nodes), 연결(edges). init 은 좌표 없이 쓴다(자동 배치).

## 스키마

```json
{
  "note": "구성요소와 연결을 그린 화면. 실행 순서는 workflow 탭. 근거는 저장소 루트 기준 파일:줄.",
  "legend": ["요청 길(주황 굵은 선): 브라우저, API 서버, DB 차례", "점선은 파일과 설정 읽기"],
  "main": ["web", "api", "db"],
  "zones": [
    { "id": "client", "label": "사용자 쪽", "color": "#1565c0" },
    { "id": "server", "label": "서버", "color": "#2e7d32" },
    { "id": "ext", "label": "외부", "color": "#757575", "dashed": true }
  ],
  "nodes": [
    { "id": "web", "zone": "client", "label": "웹 화면", "kind": "프런트엔드", "detail": "목록과 상세 화면을 그리고 /api 로 요청을 보냄", "items": ["React 18", "라우터"], "refs": ["web/src/App.tsx:1-40"], "lines": 2 },
    { "id": "api", "zone": "server", "label": "API 서버", "kind": "서비스", "detail": "요청을 검증하고 저장소 계층을 불러 JSON 으로 답함", "refs": ["server/app.js:12-60"] },
    { "id": "db", "zone": "ext", "label": "PostgreSQL", "kind": "외부", "detail": "주문과 사용자 표를 저장. 연결 문자열은 환경 변수", "refs": ["server/db.js:5"] }
  ],
  "edges": [
    { "id": "e-req", "from": "web", "to": "api", "kind": "api", "label": "HTTP /api", "detail": "fetch 로 JSON 요청", "refs": ["web/src/api.ts:8"] },
    { "id": "e-sql", "from": "api", "to": "db", "kind": "data", "label": "SQL", "refs": ["server/db.js:20-34"] }
  ],
  "scenes": [
    { "n": 1, "sec": 1.2, "focus": ["web", "e-req"], "caption": "사용자가 화면에서 요청을 보냄" }
  ]
}
```

| 키 | 형식 | 필수 | 뜻 |
|---|---|---|---|
| `note` | 문자열 | 아니오 | 탭 머리 설명 |
| `legend` | 문자열 배열 | 밀도 | "읽는 법" 목록 |
| `main` | 구성요소 id 배열 | 밀도 | 주 흐름. 이 차례로 상자가 빛남 |
| `zones[]` | `{id, label, color?, dashed?}` | 예 | 영역. `dashed` 면 점선 테두리 |
| `nodes[]` | `{id, zone, label, kind?, detail, lines?, items?, refs?, path?, planned?, color?}` | 예 | 구성요소. `zone` 은 영역 id |
| `nodes[].detail` | 문자열 | 예 | 상자 안 설명. 상자 폭으로 줄바꿈, 기본 2줄만 그림. 3줄이면 `"lines": 3`(`references/authoring.md` 의 "설명 줄 수") |
| `nodes[].items` | 문자열 배열 | 아니오 | 칩. `config.json` 의 `text.plannedPrefix`(기본 `예정`)로 시작하면 주황 |
| `nodes[].refs`, `path`, `kind` | 문자열 | 아니오 | 마우스를 올리면 보이는 근거 |
| `edges[]` | `{id?, from, to, kind?, label?, detail?, refs?, both?, color?}` | 예 | 연결. id 가 없으면 `<from>-<to>` |
| `edges[].from`, `to` | 문자열 | 예 | 구성요소 id 를 먼저 찾고 없으면 영역 id |
| `edges[].kind` | `api`, `control`, `data` | 아니오 | `api` 주황 굵은 선(요청 길), `control` 회색 실선(실행, 호출), `data` 점선(파일, 설정) |
| `edges[].refs` | 문자열 배열 | 밀도 | 근거 `파일:줄` |
| `edges[].both` | 참, 거짓 | 아니오 | 양쪽 화살표 |
| `scenes[]` | `{n, sec, focus, caption}` | 밀도 | 장면 대본. `focus` 는 구성요소 id 나 연결 id |

- 색은 `#rrggbb` 만. 그 밖은 FAIL, 화면은 기본 색
- 연결에 마우스를 올리면 `detail`, 없으면 `label` 이 보이고 뒤에 `refs`. 둘 다 없으면 `refs` 만
- `from` 과 `to` 가 같은 연결(자기 연결)은 그릴 길이 없다. `check` 가 `자기 연결` WARN

## 좌표 키

좌표는 선택이다. 아래 키가 모두 있고 유한 수일 때만 좌표를 쓴다.

| 대상 | 키 |
|---|---|
| 그림 | `width`, `height` |
| 영역 | `x`, `y`, `w`, `h` |
| 상자 | `x`, `y`, `w`, `h` |
| 연결(있을 때만 쓰는 선택 키) | `via`(`[[x, y], ...]`), `lx`, `ly`, `off`, `offTo` |

- 하나라도 빠지거나 틀리면 그 그림 전체를 자동 배치하고, 연결 선택 키는 무시한다. 좌표를 일부만 썼으면 `check` 가 WARN
- 자동 배치는 화면에 따로 알리지 않는다. 좌표를 일부만 쓴 경우는 `check` 의 WARN 으로 안다
- 영역을 끝으로 쓰는 연결은 영역 사각형 가장자리에서 나간다

## 자동 배치

목표는 가로로 넓은 그림이다(옛 운영 화면 1600 x 1000 과 비슷한 비). 영역을 띠(가로 줄)에 옆으로 놓고, 띠가 차면 다음 띠로 내려간다.

- 영역: 영역 순서대로 띠에 왼쪽부터 채운다. 띠 폭이 상한을 넘으면 다음 띠
  - 영역 순서 후보는 둘. `zones` 배열 순서, 그리고 연결이 많은 영역끼리 이웃하게 이은 순서(첫 영역에서 시작해 마지막에 놓은 영역과 연결이 가장 많은 영역을 다음에. 같으면 이미 놓은 영역 전체와 연결 수, 다음에 배열 순서)
  - 지그재그 후보: 둘째, 넷째 띠를 오른쪽부터 채운다. 앞 띠의 끝 영역 바로 아래에 다음 영역이 온다
  - 같은 띠 옆 영역 사이 틈은 48 px. 두 영역을 잇는 이름표 있는 연결이 있으면 가장 넓은 이름표 폭 + 16 px 까지 넓힌다. 이름표가 영역 테두리를 덮지 않고 틈에 들어간다
  - 띠마다 영역 폭을 똑같이 늘려 모든 띠를 가장 넓은 띠 폭에 맞춘다. 영역 높이는 그 띠에서 가장 높은 영역에 맞춘다
- 상자: 영역마다 그 영역 상자를 아래 순서대로 행 우선. 칸 수는 줄 수가 상한 이하가 되는 가장 적은 수. 상자 묶음은 영역 가운데
  - 상자 순서 후보는 둘. `nodes` 배열에서 나온 순서, 그리고 다른 영역과 잇는 연결이 4개 이상 몰린 상자만 옮긴 순서
  - 옮기는 값: 영역 순서에서 뒤 영역(영역 없는 상자 포함)과 잇는 연결 수 - 앞 영역과 잇는 연결 수. 4 이상이면 맨 뒤 칸(아래 행), -4 이하면 맨 앞 칸. 나머지 상자는 배열 순서 그대로
  - 영역 폭이 띠 폭 상한을 넘으면 칸 수를 줄이고 줄을 늘린다. 그래서 그림 폭은 띠 폭 상한 + 40 px 이하(1600 px, 넓은 후보는 1800 px)
- 영역 없는 상자(`zone` 이 영역 id 가 아님)는 맨 아래 띠에 혼자 놓는다. 테두리 없음
- 상자 크기: 영역마다 모든 상자가 같은 폭과 높이. 그 영역에서 가장 크게 필요한 상자에 맞춤
- 연결: 장애물을 피하는 가로세로 길 찾기. 모든 선분이 가로나 세로(옛 운영 화면과 같음). 대각선은 없다
  - 두 끝이 아닌 상자와 영역 제목 띠는 지나지 않는다. 같은 영역 안 연결도 같다(같은 행에서 사이 상자를 건너뛰는 연결은 그 상자를 돌아감)
  - 영역 제목 띠: 영역 이름을 쓰는 자리. 영역 왼쪽 위에서 (12, 5), 폭은 영역 이름 글 폭 x 1.3, 높이 18 px
  - 격자: 통로 가운데 선(상자 옆 틈, 같은 행 이웃 상자 사이 틈, 상자 아래 틈, 영역 사이 틈, 영역 안 상자 묶음 둘레의 넓은 빈 곳, 그림 가장자리 여백)과 상자 가운데 선. 6 px 보다 가까운 선은 하나만 둔다(상자 가운데 선이 먼저)
    - 통로 가운데 선이 그림 가장자리 여백 가운데(가장자리에서 10 px)보다 바깥이면 버린다. 영역 테두리에 가까운 선은 남긴다(다른 띠 영역 테두리에 가까워 상자 사이 틈 가운데 선이 사라지지 않게). 그 테두리를 따라 가지 못하는 것은 아래 규칙
    - 영역 제목 띠를 지나는 가로선과 세로선이 없으면 띠 가운데에 하나씩 더한다
    - 같은 띠 옆 영역 사이 틈 가운데에도 세로선을 둔다(넓힌 틈에 이름표가 들어가는 자리)
  - 격자점은 상자와 영역 제목 띠에서 8 px 넘게 떨어진 곳만 쓴다
  - 영역 테두리에서 6 px 보다 가까운 격자선(다른 띠의 상자 가운데 선 등)은 그 테두리를 따라 가지 않는다. 가로지르기만 한다
  - 끝 자리: 상자는 네 옆면에서, 옆면을 지나는 격자선마다(모서리에서 10 px 안쪽). 옆면 가운데에서 떨어진 px 마다 0.5 를 더한다. 영역 끝은 영역 테두리를 지나는 격자선마다
  - 끝 선분(옆면에서 첫 격자점까지)은 10 px 이상(화살표 길이). 끝 자리 쪽에서 되돌아 들어오는 길(제 선과 겹치고 끝 선분이 짧아짐)은 쓰지 않는다
  - 짧은 연결부터 하나씩, 값이 가장 작은 길을 고른다(A*). 값이 같으면 먼저 찾은 길. 같은 자료면 늘 같은 선
  - 값: 길이 + 꺾기 x 40 + 다른 선과 엇갈림 x 30 + 이미 다른 선이 지나는 통로 길이 x 0.5 x 그 선 수 + 같은 옆면을 쓰는 연결 수 x 12(같은 자리면 30 더)
    + 두 끝이 속하지 않는 영역 안을 지나는 길이 x 1 + 그림 가장자리 여백(가장자리에서 20 px 안)과 영역 머리 줄(영역 위 테두리에서 32 px 안)을 따라 가는 길이 x 0.5
    - 두 끝이 속한 영역은 상자 끝이면 그 상자가 든 영역, 영역 끝이면 그 영역. 관계없는 영역을 가로지르는 선은 돌아갈 길이 영역 안 길이보다 짧을 때 돌아간다
  - 통로마다 나란한 선이 들어갈 수(폭에서 20 을 뺀 폭 / 12 + 1)를 넘기면 그 통로 길이 x 4 를 더한다. 통로 폭은 양옆에서 가장 가까운 상자, 영역 제목 띠, 영역 테두리 사이
  - 이름표가 있는 연결은 이름표가 상자와 겹치지 않고(격자점에서 선분과 수직으로 6 px, 선분 방향으로 1 px 여유) 영역 테두리에서 4 px 떨어지는 곧은 구간을 지나는 길만 고른다. 그런 길이 없으면 조건 없이 고른다
  - 길을 찾지 못하면(끝 자리가 모두 막힘) 한 번 꺾은 선. 이때만 선이 상자를 지날 수 있고 `check` 가 `선이 상자 지남` WARN
- 나란한 선: 같은 방향 선분이 구간이 겹치거나 12 px 안으로 이어지면 나란한 자리로 벌린다. 관계없는 연결이 한 선분을 같이 쓰지 않는다. 혼자인 선분도 아래 범위 안으로 옮긴다
  - 간격과 상자 거리(영역 제목 띠도 같음)는 아래 차례로 처음 맞는 것. 끝내 못 맞추면 원래 줄에 둔다. 나란한 영역 테두리와 그림 가장자리에서는 늘 6 px 이상
    1. 이름표 있는 연결의 가로 선분끼리 이웃이면 20 px(이름표 높이 16 + 4), 나머지 12 px, 상자에서 10 px. 이름표 있는 가로 선분이 이웃할 때만
    2. 간격 12 px, 상자에서 10 px
    3. 간격 11 에서 6 px 까지, 상자에서 10 px
    4. 간격 12 에서 6 px 까지, 상자에서 6 px
    5. 간격 5, 4 px, 상자에서 10 px, 다음에 6 px
    6. 간격 12 에서 3 px 까지, 상자에서 3 px
  - 단계마다 먼저 이름표 있는 선과 100 px 넘는 선분은 나란한 영역 테두리에서 12 px, 이름표 있는 가로 선분은 상자에서 13 px(이름표 반 높이 8 + 5) 떨어뜨려 보고, 안 되면 6 px 과 위 상자 거리로
  - 끝 선분에 이어지는 선분은 끝 상자에서 10 px 이상(끝 선분이 화살표 길이 이상). 끝 자리는 옆면 모서리에서 10 px 안쪽
  - 차례: 원래 줄 좌표, 다음에 먼저 끝나는 쪽 끝에서 꺾는 방향(위, 왼쪽으로 꺾으면 앞 자리). 엇갈림이 덜 생긴다
  - 벌린 뒤 다른 묶음 선과 12 px 보다 가까우면 두 묶음을 합쳐 다시 벌린다
- 이름표: 선을 모두 그은 뒤 놓는다. 후보 자리는 그 연결의 선분을 긴 차례로, 선분마다 17곳. 0.5 에서 시작 쪽으로 0.1 까지, 다음에 끝 쪽으로 0.55 에서 0.9 까지(0.05 간격)
  - 상자와 겹치지 않는 후보가 없으면 선분마다 가운데부터 4 px 간격으로 더 본다
  - 그림 밖으로 나가는 후보는 그림 안(가장자리에서 1 px 안쪽, 테두리 선 굵기 포함)으로 민다
  - 상자와 겹치지 않는 후보가 적은 이름표부터 놓는다(같으면 연결 차례)
  - 상자와 겹치지 않고 상자에서 5 px 이상, 앞서 놓은 이름표와 4 px 이상 떨어지고, 영역 이름과 영역 테두리를 가리지 않고, 다른 연결의 선과 4 px 이상 떨어진 첫 곳에 놓는다. 영역 테두리는 4 px 안에 들어와도 가린 것으로 센다
  - 그런 곳이 없으면 (덮는 상자 수, 5 px 안 상자 수, 가까운 이름표 수, 가리는 영역 이름과 영역 테두리 수, 4 px 안의 다른 선 수)가 가장 작은 첫 곳에 놓는다. 상자를 덮으면 `check` 가 `이름표 덮음` WARN
- 배치 고르기: 아래 후보를 놓아 보고, 그 가운데 몇 개만 선을 그어 하나를 고른다
  - 후보: 순서(영역 순서 2 x 상자 순서 2, 같은 것은 하나) x 띠 폭 상한(1200, 1400, 1560 px) x 영역 안 줄 수 상한(1 부터 가장 많은 영역의 상자 수까지) x 띠 방향(왼쪽부터, 지그재그)
  - 값: 높이 + (`선이 상자 지남`, `이름표 덮음`, `이름표가 그림 밖` 수) x 60 + 선 길이 합 x 0.1 + 엇갈림 수 x 10 + 붐비는 이름표 수 x 30
    + 다른 영역 안 길이 x 0.3 + (좁은 나란한 선 쌍 수 + 테두리 붙은 긴 선분 수) x 20
    - 엇갈림은 다른 연결의 가로 선분과 세로 선분이 두 선분 안쪽에서 만나는 곳
    - 붐비는 이름표는 놓은 자리에서 상자에서 5 px 안이거나 영역 이름이나 영역 테두리를 가리거나 다른 선이 4 px 안에 있는 이름표
    - 다른 영역 안 길이는 선분이 두 끝이 속하지 않는 영역 사각형 안을 지나는 길이 합
    - 좁은 나란한 선 쌍은 다른 연결의 같은 방향 선분이 20 px 넘게 함께 달리며 12 px 보다 가까운 쌍. 테두리 붙은 긴 선분은 영역 테두리와 100 px 넘게 나란히 12 px 안을 달리는 선분
    - 가중치 근거: 다른 영역 1 px 의 0.3 은 선 길이 1 px 의 3배(관계없는 영역을 지나는 선은 길이보다 읽기를 크게 해침. 0.5 로 하면 영역을 피하려고 그림이 세로로 길어짐). 좁은 쌍 하나의 20 은 엇갈림 둘, 높이 20 px 과 같음
    - 상자 20개 이상이고 가로세로 비가 1.2 아래면 모자란 폭(1.2 x 높이 - 폭)을 높이에 더한다
  - 선을 긋기 전에 아래 한계(높이 + 두 끝 사각형 사이 가로세로 거리 합 x 0.1, 비가 모자라면 위와 같이 더함)를 잰다. 선은 두 끝 사이 거리보다 짧을 수 없다
  - 비 하한을 맞춘 후보를 앞에, 다음에 아래 한계가 작은 차례(같으면 먼저 만든 후보)로 줄 세워 앞 3개만 선을 긋는다. 그 가운데 앞서 고른 후보 값보다 아래 한계가 큰 후보는 긋지 않는다
  - 고르는 기준(앞 기준이 같을 때만 다음 기준)

    | 순서 | 기준 |
    |---|---|
    | 1 | 상자 20개 이상이면 가로세로 비(폭 / 높이) 1.2 이상 |
    | 2 | 위 값이 가장 작음 |
    | 3 | 먼저 만든 후보(배열 순서, 띠 폭 상한이 작은 것, 줄 수 상한이 작은 것, 왼쪽부터 채우기 차례) |

  - 고른 후보에서 아래 틈을 넓혀 한 번 더 놓고 그어 본다. 값이 더 작고 기준 1 을 지키면 바꾼다
    - 같은 띠 옆 영역 사이 틈: 그 틈을 지나는 세로 선분을 구간이 이어지는 묶음으로 나눠 가장 큰 묶음의 선 수가 n 이면 (n - 1) x 12 + 24 px. 지금 틈보다 넓을 때만
    - 띠 사이 틈: 가로 선분으로 같은 방법
    - 영역 안 상자 사이 가로 간격: 같은 행 이웃 상자를 곧게 잇는 이름표 있는 선의 이름표가 상자에서 5 px 안이면 이름표 폭 + 12 px(76 px 이하일 때만)
  - 1560 px 후보로 기준 1 을 못 맞추면 띠 폭 상한 1760 px 후보도 같은 방법으로 보고, 위 기준으로 더 나은 쪽을 고른다
  - 같은 그림이 되는 후보는 한 번만 본다. 같은 자료면 늘 같은 배치

## 자동 배치 WARN 줄이기

- 자동 배치는 선이 상자를 지나지 않게 돌아간다. 남는 WARN 은 이름표가 들어갈 곳이 없을 때의 `이름표 덮음`, `이름표가 그림 밖` 이다. 배치 조언이고 실패가 아니다
- 아래 할 일은 WARN 이 없어도 선을 짧게 하고 꺾기와 엇갈림을 줄인다
- 밀도 하한(연결 15 등)을 지키는 것이 먼저다. WARN 을 없애려고 실제 연결을 지우지 않는다
- 아래 순서로 줄인다

  | 순서 | 할 일 | 효과 |
  |---|---|---|
  | 1 | `zones` 를 주 흐름 차례로 놓는다. 연결이 많은 두 영역을 배열에서 이웃하게(자동 배치도 연결이 많은 영역끼리 이은 순서를 후보로 보지만 배열 순서가 출발점) | 이웃 영역은 같은 띠 옆이나 바로 아래 띠에 놓여 선이 짧아짐 |
  | 2 | 영역 안 `nodes` 순서를 바꾼다. 같은 영역 안에서 서로 잇는 상자를 이웃 칸(같은 행 옆, 같은 칸 위아래)에 | 같은 영역 안 연결이 사이 상자를 돌아가지 않아 직선이 됨 |
  | 3 | 상자가 많은 영역을 둘로 나눈다(영역 하한 5 에도 도움) | 영역 사이 연결이 되어 꺾은선으로 돌아갈 수 있음 |
  | 4 | 한 영역의 여러 상자로 가는 같은 뜻의 연결은 끝을 영역 id 로 한 줄에 | 선 수가 줄어 통로가 덜 붐빔. 연결 하한 아래로는 묶지 않음 |
  | 5 | 그래도 많으면 좌표를 모두 쓴다(위 "좌표 키") | 좌표 사용에서는 같은 검사가 FAIL 이 되므로 모두 고쳐야 함 |

- 남은 WARN 수는 사용자에게 보고한다

### 연결 방향으로 영역 나누기

- 영역은 영역 순서(배열 순서, 또는 연결이 많은 영역끼리 이은 순서)대로 띠에 옆으로 놓이고, 띠가 차면 다음 띠로 내려간다. 불리는 쪽 영역을 부르는 쪽 영역 바로 뒤에 둔다
- 외부 구성요소를 맨 끝 "외부" 영역 하나에 모으지 않는다. 부르는 쪽마다 나눠 그 바로 뒤에 둔다
  - 예: 화면이 부르는 외부 API 는 "외부(화면이 부름)" 영역을 화면 영역 바로 뒤에
  - 예: 서버가 부르는 DB 는 "외부(서버가 부름)" 영역을 서버 영역 바로 뒤에
- 효과: 선이 먼 영역을 건너지 않아 꺾은선이 짧고 꺾기와 엇갈림이 줄어듦. 영역 하한 5 에도 도움

### 여러 상자가 한 상자로 모일 때

- 여러 상자에서 한 상자로 가는 연결(예: 네 모듈이 모두 같은 설정 파일을 읽음)은 끝이 한 점에 모인다
- 받는 상자를 보내는 상자들의 영역 바로 뒤 영역에 따로 둔다. 같은 영역에 두면 선이 이웃 상자를 돌아가 길어진다
- 같은 뜻의 연결이면 보내는 쪽 끝을 영역 id 로 한 줄에 묶는다(위 표 4). 연결 하한 아래로는 묶지 않는다
- 묶지 못하면 이름표는 한 연결에만 달고 나머지는 이름표 없이 `detail` 에 뜻을 쓴다. 이름표가 모이는 곳에서 서로 밀어내기 때문이다

### `이름표 덮음` 줄이기

- 원인: 이름표가 상자와 겹치지 않는 곧은 구간을 지나는 길이 없을 때. 이름표가 아주 길거나 상자가 빽빽할 때
- 같은 행 이웃 상자 사이 연결의 이름표 글 폭이 48 px 를 넘으면 선이 행 사이나 영역 사이로 돌아가 길어진다
- 아래 순서로 줄인다
  1. 같은 행 이웃 상자 사이 연결의 이름표는 글 폭 48 px 이하로 쓴다(한글 4자, 또는 영문 8자). 예: `SQL 읽기`(45 px). 선이 곧게 이웃 상자로 간다
  2. 그 연결을 다른 영역 사이 연결로 바꾼다(위 "연결 방향으로 영역 나누기"). 영역 사이 거리 80~120 px 에서는 이름표가 들어간다
  3. 같은 두 끝을 잇는 연결이 여럿이면 하나로 합치고 `detail` 에 나머지 뜻을 쓴다
  4. 이름표가 꼭 필요하지 않은 연결은 `label` 을 빼고 `detail` 만 쓴다. `label` 은 밀도 항목이 아니다
- 이름표를 줄이려고 연결을 지우지 않는다

### 배치 후보 비교

- 배치 후보는 최대 3개 만든다. 후보마다 위 표 1~4 가운데 다른 조합을 쓴다(예: 영역 순서만, 영역 순서와 상자 순서, 영역 나누기까지)
- 자료 폴더를 임시 폴더에 복사하고 후보마다 사본의 `arch.json` 만 바꿔 검사한다
  - `node "<S>/scripts/progress-mon.mjs" check --runtime <rt> --data <사본 폴더>`
- 고르는 기준(앞 기준이 같을 때만 다음 기준을 본다)

  | 순서 | 기준 |
  |---|---|
  | 1 | FAIL 0 |
  | 2 | `선이 상자 지남`, `이름표 덮음`, `이름표가 그림 밖` WARN 합이 가장 적음 |
  | 3 | `이름표 덮음` 이 더 적음 |
  | 4 | `zones` 순서가 `main` 차례에 더 가까움 |

- 고른 후보의 `arch.json` 만 실제 자료 폴더에 쓴다. 사본 폴더는 지운다
- 3개로도 WARN 이 남으면 남은 수를 사용자에게 보고하고 멈춘다. 좌표를 모두 쓸지는 사용자가 정한다

## check 항목

| 검사 | 좌표 사용 | 자동 배치 |
|---|---|---|
| 형식, 필수 키, id 겹침, 연결 끝, 영역, 장면 대상, `main`, 색 | FAIL | FAIL |
| 상자 겹침, 영역 겹침 | FAIL | FAIL(배치가 막음) |
| 영역 밖, 그림 밖 | FAIL | FAIL(배치가 막음) |
| 글 넘침(이름, 설명, 칩, 내용이 상자 아래로) | FAIL | FAIL |
| 선이 상자 지남 | FAIL | WARN(길 찾기가 돌아가므로 길을 찾지 못한 연결만) |
| 이름표 덮음, 이름표가 그림 밖 | FAIL | WARN |
| 설명이 `lines` 보다 김(잘림) | WARN | WARN |
| 상자 60개, 연결 60개 초과 | WARN(크기 지침) | WARN |

- 자동 배치의 WARN 은 실패가 아니다. 줄이는 법은 위 "자동 배치 WARN 줄이기"
