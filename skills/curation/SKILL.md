# curation — 결정 큐레이션 (선택지·권고·확신)

의사결정 국면에서 답을 단정하기 전에, **판단을 감사(監査) 가능한 형태로 펼쳐** 보여준다.
"그냥 골라주기"가 아니라 **선택지 → 권고 → 근거 → 확신수준 → 확신 근거**를 명시해,
사용자가 권고를 검증·재정(裁定)할 수 있게 한다.

**런타임:** 이 스킬은 외부 도구·프레임워크 의존이 **전혀 없다**(순수 출력 규약).
Claude Code(OMC)·Codex CLI(OMX) 양쪽에서 **동일하게** 동작한다.

## 언제 쓰나
- 하나 이상의 **실질적 결정 분기**가 있는 작업(설계 선택, 트레이드오프, 우선순위, 배포 여부 등).
- 사용자가 "curation"/"큐레이션"/"결정 정리"/"선택지 보여줘"라고 요청할 때.
- 되돌리기 어렵거나 파급이 큰 결정 — 확신수준을 명시해 리스크를 드러낼 때.

## 쓰지 않을 때
- 결정 분기가 없는 단순 실행(그냥 하면 됨).
- 사실 조회·계산처럼 "정답"이 하나인 질문(선택지가 인위적이면 형식 낭비).

## 출력 형식 (필수 5요소)
각 결정마다:

1. **선택지** — 상호배타적·현실적인 옵션 2개 이상. 억지 옵션 금지.
2. **권고안** — 선택지 중 하나. 반드시 선택지에서 고른다(제3의 답 금지).
3. **권고 근거(사유)** — 왜 그 옵션인가. 핵심 결정 동인(driver) 기준.
4. **확신수준** — `0.00`~`1.00`. 추측 금지, 보정된 값.
5. **확신수준 근거** — 왜 그 수치인가(무엇이 확신을 높이고/낮추는가, 미해결 변수).

결정이 여럿이면 **표**로 압축하고, 단일 결정은 블록으로 상술한다.

### 표 형식 (다중 결정)
| # | 사안 | 선택지 | 권고 | 확신 | 근거 / 확신근거 |
|---|---|---|---|---|---|
| 1 | … | A / B / C | **B** | 0.70 | 근거 … / 확신근거 … |

### 블록 형식 (단일 결정)
- **사안**: …
- **선택지**: A / B / C
- **권고안**: **B**
- **권고 근거**: …
- **확신수준**: 0.70
- **확신수준 근거**: …

## --perf (performance = 품질 우선)
`curation --perf` 로 부르면, 위 형식에 **채택 기준**을 하나 추가한다:

> 권고안을 고를 때 **구현 노력 효율·토큰 효율·시간 절약보다 결과물의 품질·완성도가 훨씬 중요**하다.

→ 저노력·저비용이지만 품질이 낮은 옵션과, 노력·비용이 크지만 완성도가 높은 옵션이 맞설 때
`--perf`는 **후자(품질)로 기운다**. 권고 근거·확신근거에 이 기준이 어떻게 작용했는지 드러낸다.
(기본 curation은 노력·품질·시간을 **균형** 있게 저울질한다.)

## 적용 범위
- 호출 시점의 **현재 작업/요청에 걸린 결정들**에 이 형식을 적용한다.
- 이후에도 같은 작업 맥락에서 결정이 나오면 형식을 유지한다(사용자가 바꾸라기 전까지).
- 결정을 대신 **집행**하지는 않는다 — 권고를 제시하고, 사용자 재정 후 진행한다
  (되돌리기 어려운 행위는 특히).

## 예시
**입력**: `curation --perf` "로그 저장을 파일 vs SQLite 중 뭘로?"

**출력**:
- **사안**: 로그 영속화 백엔드
- **선택지**: 파일(JSONL) / SQLite
- **권고안**: **SQLite**
- **권고 근거**: 조회·집계·동시쓰기 내구성에서 우월. 파일은 초기 구현이 싸지만 질의·회전(rotation)·잠금을 직접 떠안아 완성도가 낮아진다.
- **확신수준**: 0.75
- **확신수준 근거**: 질의·집계 요구가 확실하면 SQLite 우위가 뚜렷(↑). 단 로그량·배포 환경(임베디드 등)이 미확인이면 파일이 나을 여지(↓). `--perf`라 "싸고 대충"인 파일보다 완성도 높은 SQLite로 기울였다.

## 함정
- **선택지 억지 금지** — 결정이 없는데 형식을 씌우지 말 것.
- **권고는 선택지 안에서** — 제3의 절충안을 슬쩍 끼우면 감사 가능성이 깨진다(정 필요하면 그것도 선택지로 명시).
- **확신수준은 정직하게** — 높게 부풀리지 말 것. 미해결 변수가 있으면 낮추고 그 이유를 확신근거에 적는다.
- **--perf ≠ 무조건 비싼 옵션** — 품질이 동등하면 효율적 옵션을 택한다. --perf는 품질이 갈릴 때의 **타이브레이커**다.

ARGUMENTS: [--perf] [결정 맥락/질문] (없으면 현재 작업의 결정 분기에 적용)
