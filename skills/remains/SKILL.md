# remains - 남은 버그, 하자, 미검증 항목 표

지금 작업에 남은 버그, 하자, 미검증 항목을 찾아 표 하나로 보여 준다. 테스트박스가 등록돼 있으면 같은 시험을 각 OS 에서 돌려 미검증을 줄인다.
읽기와 시험 실행만 한다. 답변은 한글.

## 원칙

- 고치지 않는다. 코드 수정, 커밋, push, 의존성 설치, 유료 API 호출을 하지 않는다. 무엇을 고칠지는 사용자가 표를 보고 정한다.
- 확인한 것과 확인하지 못한 것을 섞지 않는다. 돌려 보지 않은 것은 통과로 적지 않고 미검증으로 적는다.
- 박스가 없거나 접속되지 않으면 다른 원격 실행(CI 를 돌리려는 push 등)으로 대신하지 않는다. 그 OS 는 미검증으로 남긴다.
- 표와 근거에 비밀값(키, 토큰, 비밀번호, 크레덴셜 파일 내용)을 싣지 않는다.

## 1. 범위

- 대상은 현재 저장소다(`git rev-parse --show-toplevel`). 저장소가 아니면 현재 폴더와 이번 대화의 작업만 본다.
- 기준점은 인자로 준 커밋이다. 없으면 마지막 태그(`git describe --tags --abbrev=0`), 그것도 없으면 기본 브랜치와의 merge-base 를 쓴다.
- 기준점 이후의 커밋, 커밋하지 않은 변경, push 하지 않은 커밋을 모두 범위에 넣는다.

## 2. 남은 항목 모으기 (읽기만)

| 출처 | 보는 것 |
|---|---|
| 이번 대화 | 미검증이나 보류로 남긴 것, 검토의 비차단 지적, 사용자가 미룬 결정, 보고했지만 확인하지 않은 주장 |
| 저장소 기록 | 인계 문서(예: `.omc/handoffs/`), CHANGELOG `[Unreleased]` 의 `UNVALIDATED` 나 미검증 표기, 문서의 미검증 절 |
| 코드 표시 | 범위 안에서 바뀐 파일의 `TODO`, `FIXME`, `XXX`, `HACK`, 시험의 `skip`, `only`, `todo` |
| git 상태 | 커밋하지 않은 변경, push 하지 않은 커밋, 추적하지 않는 새 파일 |
| 메모리와 노트 | 있으면 그 안의 남은 지적 |

## 3. 이 머신에서 시험

- 프로젝트의 시험 명령을 찾는다. `package.json` 의 `scripts.test`, CI 워크플로의 시험 단계, `Makefile`, pytest 설정, `*.test.mjs`(node:test) 순으로 본다. 찾은 명령과 그 근거를 확인 범위에 적는다.
- 의존성을 설치하지 않는다. 의존성이 없어 못 돌리면 미검증으로 적는다.
- 실패한 시험은 이름과 첫 오류 줄을 근거로 남긴다. 건너뛴 시험은 건너뛴 이유를 확인하고, 환경 때문이면 미검증으로 적는다.
- 프로젝트에 설정되고 이미 설치된 린트, 형식 검사, 타입 검사가 있으면 함께 돌린다. 검사만 하는 방식(`--check` 등)으로 돌리고, 파일을 고치는 `--write`, `--fix` 는 쓰지 않는다.

## 4. 테스트박스 (등록돼 있으면)

박스 작업은 이 스킬 폴더의 `scripts/boxes.mjs` 가 한다(Codex 에서는 `~/.codex/skills/banker-remains/scripts/boxes.mjs`). Node 만 쓰고, 이 머신에 `ssh`, `scp`, `git`, 박스에 `tar` 가 있어야 한다. `--no-boxes` 를 받으면 이 단계를 건너뛰고 확인 범위에 그렇게 적는다.

1. `node <스킬 폴더>/scripts/boxes.mjs list` 로 등록을 본다. 등록 파일이 없으면 확인 범위에 "테스트박스 미등록" 이라 적고 넘어간다.
2. `node <스킬 폴더>/scripts/boxes.mjs probe` 로 접속을 확인한다.
   - 접속되지 않는 박스는 그 OS 를 미검증으로 적고, ssh 가 낸 이유를 근거로 둔다.
   - 시험에 필요한 런타임이 없는 박스(예: `--node-test` 인데 `node` 가 `null`)는 `--box` 로 빼고 미검증으로 적는다.
3. 같은 시험을 모든 박스에서 동시에 돌린다. 저장소 루트에서 실행한다.
   - node:test 프로젝트: `node <스킬 폴더>/scripts/boxes.mjs run --node-test --ref worktree`
   - 그 밖: `node <스킬 폴더>/scripts/boxes.mjs run --cmd "<시험 명령>" --ref worktree`
   - Claude Code 에서는 Bash 도구의 시간 제한이 시험보다 짧을 수 있으므로 백그라운드로 실행한다.
   - `--node-test` 는 `*.test.mjs` 만 돌린다. 다른 종류의 시험(Python, `.test.ts` 등)은 `--cmd` 로 따로 돌리거나 그 OS 에서 미검증으로 적는다.
   - 보내는 것은 추적하는 파일의 커밋된 내용 그대로다(줄 끝 변환 없음). `--ref worktree` 는 커밋하지 않은 추적 파일의 변경까지 보낸다. 추적하지 않는 새 파일은 보내지 않는다(출력의 `untracked`). 그 파일이 시험에 필요하면 미검증으로 적는다.
   - Windows 박스에서는 명령이 `.cmd` 파일 안에서 돈다. 명령이 OS 마다 달라야 하면 `--box <이름>` 으로 나눠 돌린다.
   - 오래 걸리면 `--timeout <분>`(기본 20)을 늘린다.
4. 출력 JSON 의 박스별 `summary`(tests, pass, fail, skipped, failures)와 `log` 파일을 근거로 쓴다. 종료 코드는 다음과 같다.
   - 0: 모든 박스가 통과
   - 1: 접속 실패, 시험 실패, 시간 초과, 시험 0건(`noTests`), 정리 실패(`cleaned: false`) 중 하나가 있음
   - 2: 사용법이나 등록 파일 오류
   - 130, 143: SIGINT, SIGTERM 으로 멈춤(정리는 마침)
5. 박스의 실패를 바로 버그로 적지 않는다. 먼저 로그로 원인을 구분한다.
   - 명령의 종료 코드 127(명령을 찾지 못함)은 그 박스에 런타임이 없다는 뜻이라 미검증이다.
   - 97(보낸 트리로 들어가지 못함)은 도구나 박스 문제라 미검증으로 적고 이유를 남긴다.
   - `noTests` 는 시험이 하나도 돌지 않았다는 뜻이라 통과가 아니라 미검증이다.
   - 한 OS 에서만 실패하면, 제품의 결함은 버그로, 시험이 실행 환경을 잘못 가정한 것은 하자로 적는다.

박스에 둔 것은 `run` 이 끝날 때 지운다. 시간 초과, 연결 끊김, 중단(SIGINT, SIGTERM) 때는 박스에서 시작한 프로세스를 먼저 끝낸다. Linux, macOS 는 `mktemp -d` 로 만든 개인 폴더를 쓴다. 지우지 못하면 결과의 `cleaned` 가 `false` 이고, 그 박스를 하자로 적는다.

### 등록 파일

`~/.config/banker/test-boxes.json` 이다(`BANKER_TEST_BOXES` 로 다른 파일을 가리킬 수 있다).

```json
{
  "boxes": [
    { "name": "macos", "os": "darwin", "ssh": "user@mac-host", "path": ["/usr/local/bin"] },
    { "name": "windows", "os": "win32", "ssh": "user@windows-host" },
    { "name": "linux", "os": "linux", "ssh": "root@linux-host", "runAs": "nobody" }
  ]
}
```

| 항목 | 뜻 |
|---|---|
| `name` | 박스 이름(영문이나 숫자로 시작, 영문, 숫자, `.`, `_`, `-`) |
| `os` | `linux`, `darwin`, `win32` 중 하나 |
| `ssh` | `user@host`. 암호 없이 SSH 키로 접속돼야 한다 |
| `port`, `identity` | 선택. SSH 포트와 키 파일 경로 |
| `path` | 선택. Linux, macOS 박스에서 PATH 앞에 붙일 절대 경로(비대화형 SSH 의 PATH 에 node 가 없을 때) |
| `runAs` | 선택. root 로 접속하는 Linux 박스에서 시험을 대신 돌릴 계정(예: `nobody`) |

- 비밀번호나 토큰 칸은 받지 않는다. 모르는 칸이 있으면 오타로 보고 멈춘다.
- 파일은 사용자가 만든다. 사용자가 박스 정보를 주면, 이 형식으로 만들기 전에 내용을 보여 주고 확인받는다.
- 처음 접속하는 박스의 호스트 키는 `~/.ssh/known_hosts` 에 더해진다(`StrictHostKeyChecking=accept-new`). 이미 아는 박스의 키가 바뀌면 접속하지 않는다.

## 5. 분류

| 종류 | 뜻 | 예 |
|---|---|---|
| 버그 | 동작이 틀렸고 재현된다 | 실패한 시험, 틀린 결과, 한 OS 에서만 나는 오류 |
| 하자 | 동작은 하지만 품질에 문제가 있다 | 규칙 위반, 문서와 코드의 불일치, 결함을 못 잡는 시험, 남은 임시 파일 |
| 미검증 | 확인하지 못했다 | 박스가 없는 OS, 실제 외부 API, 손으로만 하는 단계, 돌리지 못한 시험 |

- 심각도는 세 단계다.
  - 높음: 데이터 손실, 보안, 사용자 작업이 막힘
  - 중간: 기능 일부가 틀리지만 우회할 수 있음
  - 낮음: 불편, 문서, 정리

## 6. 출력

1. 첫 줄: 종류별 남은 항목 수와 가장 심각한 항목.
2. 확인 범위: 기준점, 돌린 시험과 결과(이 머신과 박스별 통과, 실패, 건너뜀), 확인하지 못한 OS.
3. 표:

| # | 항목 | 종류 | 심각도 | 근거 | 확인한 곳 | 다음 조치 |
|---|---|---|---|---|---|---|
| 1 | 무엇이 남았나 | 버그 | 높음 | `파일:줄`, 실패한 시험 이름, 명령 | Windows 박스 | 무엇을 하면 닫히나 |

- 근거는 다시 확인할 수 있게 쓴다(파일과 줄, 명령, 시험 이름, 로그 경로).
- 심각도가 높은 것부터 놓는다.
- 남은 항목이 없으면 표 대신 "남은 항목 없음" 과 확인 범위를 쓴다.
- 마지막 줄에는 사용자가 고를 다음 행동을 쓴다(예: 고칠 항목 고르기). 고치는 일은 요청을 받은 뒤에 한다.
