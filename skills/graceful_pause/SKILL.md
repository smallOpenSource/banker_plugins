# graceful_pause: 지금 단계만 끝내고 멈춤

인자: `$ARGUMENTS`
- 선택. 멈춘 뒤 다룰 지시나 메모
- Codex: 사용자 메시지에서 읽음

## 동작 시점

- 작업 도중 사용자가 대기 입력으로 넣어 두면, 큐에서 넘어와 이 스킬을 읽는 시점에 동작
- 즉시 끊는 장치 없음. 읽기 전에 끝난 동작은 되돌리지 않음
- 바로 끊어야 하면 Esc. 이 스킬의 몫이 아님
- 함께 들어온 다른 대기 입력: 이 스킬 먼저 처리. 나머지는 정지 보고의 "받은 지시"에 넣음
- 이미 작업이 끝난 뒤에 읽혔으면 1단계와 2단계는 건너뛰고 정지 보고부터 시작

## cancel 과 차이

| 항목 | graceful_pause | cancel |
|---|---|---|
| 진행 중인 단계 | 끝까지 마무리 | 그 자리에서 중단 |
| 켜져 있는 모드 | 그대로 둠 | 실행을 끝냄 |
| 모드가 남기는 기록 | 손대지 않음 | 모드마다 다름. ralph 상태는 지우고, autopilot 진행 상황과 ultragoal 원장은 남김 |
| 이후 | 지시를 받아 같은 흐름 재개 | 모드를 다시 시작해 남은 기록부터 이어 감 |

## 절차

1. 지금 단계 확인
   - 지금 단계: 이미 시작한 도구 동작 하나와, 그 동작이 남긴 불일치를 닫는 최소 작업
   - 예: 함수 이름을 바꾸던 중이면 그 이름을 쓰는 곳까지 바꿈
   - 포함하지 않음: 스토리나 할 일 목록의 다음 항목
2. 지금 단계 마무리

   | 진행 중인 동작 | 처리 |
   |---|---|
   | 파일 수정 | 그 파일을 일관된 상태까지 수정. 반쯤 고친 파일을 남기지 않음 |
   | 실행 중인 명령이나 테스트 | 결과 받기 |
   | 백그라운드 작업 | 멈추지 않음. 이름과 출력 위치만 기록 |
   | 이미 띄운 하위 에이전트 | 결과를 기다리거나 백그라운드로 둠. 새로 띄우지 않음 |

3. 하지 않는 것
   - 다음 단계 시작 (예: 다음 파일, 다음 스토리)
   - 되돌리기 어려운 동작
     - 커밋과 push
     - 배포와 게시
     - 삭제와 외부 전송
   - 모드 상태와 계획 파일 삭제. `cancel` 실행
4. 정지 보고. 대화에만 짧게

   | 항목 | 내용 |
   |---|---|
   | 끝낸 단계 | 방금 마무리한 것 |
   | 현재 상태 | 검증 결과와 커밋하지 않은 변경 |
   | 진행 중인 것 | 실행 중인 백그라운드 작업과 켜져 있는 모드 |
   | 다음 예정 단계 | 1개에서 3개 |
   | 열린 결정 | 사용자 판단이 필요한 것 |
   | 받은 지시 | 인자 메모와 함께 들어온 대기 입력. 그 지시가 계획에 주는 영향 |

5. 지시 대기

   | 런타임 | 방법 |
   |---|---|
   | Claude Code | `AskUserQuestion` 으로 질문. 선택지는 계획대로 계속, 지시 반영 후 계속(자유 입력), 상태를 둔 채 중단. 질문이 열려 있는 동안은 응답이 끝나지 않으므로 ralph 같은 지속 모드도 끼어들지 않음 |
   | Codex | 구조화 질문 도구(`request_user_input` 등)가 있으면 사용. tmux 안이면 `omx question` 도 가능. 둘 다 없을 때는 아래 표 |

   - Codex 에서 질문 도구가 없을 때

     | 지속 모드 (ralph, ultraqa, team 등) | 처리 |
     |---|---|
     | 꺼짐 | 짧은 질문 하나로 응답 종료 |
     | 켜짐 | 응답을 끝내도 그 모드의 Stop 훅이 작업을 다시 이어 가게 하므로 멈출 수 없음. 이 사실을 정지 보고에 적고, 계속할지 `cancel` 할지 묻기 |

6. 재개

   | 사용자 답 | 처리 |
   |---|---|
   | 계속 | 다음 예정 단계부터 진행 |
   | 새 지시 | 영향받는 단계를 다시 계획. 범위가 바뀌면 바뀐 계획을 먼저 보여 주고 승인 뒤 진행 |
   | 중단 | 상태를 둔 채 멈춤. 세션을 끝낼 예정이면 `ready-compact --hand-off` 로 새 세션용 노트와 프롬프트 준비를 안내 |
   | 취소 | 사용자가 명시할 때만 `cancel` 실행 |

   - 중단 중인 지속 모드
     - Claude Code: 응답이 끝날 때마다 OMC Stop 훅이 한 번씩 계속하라는 메시지를 넣음. 사용자가 재개를 말할 때까지 작업을 진행하지 않고 정지 중이라는 한 줄만 답함
     - 예외: 직전 출력이 `ready-compact` 의 resume 프롬프트였다면 그 한 줄 대신 같은 프롬프트를 그대로 다시 출력. 마지막 메시지가 프롬프트여야 `/copy` 가 맞는 것을 복사함
     - 이 메시지까지 멈추려면 `cancel` 이 필요함을 알림. 그 모드가 남기는 기록은 위 표의 cancel 열

## 함정

- 정지 보고를 핑계로 다음 단계를 미리 하지 않음
- 정지 중 받은 계속 신호(훅 메시지)는 사용자 승인이 아님. 사용자가 재개를 말할 때까지 모든 응답에 해당
- 정지 중 도착한 백그라운드 작업 결과: 보고에 추가만 함. 후속 작업은 시작하지 않음
