# refresh-readme: README 드리프트 해소 (코드와 문서 정합)

README 는 저장소에서 가장 먼저 읽히면서 가장 늦게 고쳐지는 파일이다.
코드는 릴리스마다 움직이는데 README 의 산문은 작성 시점에 멈춰 있고, 그 차이는 **어떤 테스트도 잡지 않는다.**
이 스킬은 그 드리프트를 코드 쪽 사실과 대조해 찾아내고, README 를 현재 프로젝트에 맞게 고쳐 쓴다.

임무는 **정확성**이다. 고쳐 쓸 때의 품질 기준(누락 없이 간결하게, 감탄사·과장·이모지 없이)은
갱신물이 지켜야 할 조건이지 임무 자체가 아니다. 답변은 한글(기술 토큰·경로·명령은 영문).

**런타임:** 런타임 무관하다. 대상은 저장소 안의 README 파일이고, 필요한 건 파일 읽기·쓰기와 `git`·`grep` 뿐이다.
Claude Code(OMC)·Codex CLI(OMX) 양쪽에서 동일하게 동작한다.
**마크다운 파서 라이브러리를 끌어오지 마라.** banker 는 dependencies 0 이다. 대조도 검증도 무의존으로 푼다.

## When to use
- 코드가 움직였는데 README 가 따라오지 않았을 때: 기능 추가·삭제, 이름 변경, 개수 변화, 명령·경로 변경.
- 릴리스 직전에 README 의 산문 주장이 실제와 맞는지 확인할 때.
- README 가 레퍼런스 문서로서 읽기 나쁠 때(감탄사·과장·이모지). 이건 갱신에 딸려 처리한다.
- 사용자가 `refresh-readme`/`README 갱신`/`README 최신화`/`README 드리프트` 라고 할 때.

## When NOT to use
- **README 가 아닌 파일.** 범위는 README 파일뿐이다. SKILL.md·CHANGELOG·주석·위키는 밖이다.
- **코드 슬롭 정리.** `ai-slop-cleaner`(OMC 네이티브) 소관이다. 그건 **코드 전용**이고 자기 문서에서 "clean up formatting" 을 명시적 비적합으로 선언한다. 산문·README 는 대상이 아니다. banker 는 OMC 네이티브를 중복 번들하지 않는다.
- **영문 산문 윤문.** `humanizer`(banker) 소관이다. 스코프가 **영문 산문**이고 기본 자세가 개성·1인칭 주입이라, 한국어 레퍼런스 문서에는 역행한다. README 가 영문이고 목적이 "읽는 맛"이면 그쪽으로 보내라.
- **`.gitignore` 정리.** `refresh-git-ignore` 소관이다. 구조가 형제일 뿐 대상 파일이 다르다. 그 스킬은 README 를 보지 않는다.
- **없는 README 를 새로 쓰는 것.** 이건 드리프트 해소지 작성이 아니다. 초안이 필요하면 별도 지시로 간다.

## 고정 정책 (범위·품질 기준)
- **대상: README 파일만.** 기본은 저장소 루트 하나. 여러 개면 목록을 제시하고 확인받는다.
- **사실은 코드에 있다.** README 를 근거로 README 를 고치지 마라. 문서 안에서 아귀가 맞아도 코드와 틀릴 수 있다.
- **드리프트 판정이 난 문장만 고친다.** 전면 재작성 금지. 문서를 통째로 다시 쓰면 검토 불가능한 diff 가 나오고 그 안에 새 오류가 섞인다.
- **갱신물의 품질 기준** (고쳐 쓸 때 챙길 조건):
  - **누락 없이 간결하게.** 사실을 빼서 짧게 만드는 건 간결이 아니라 손실이다.
  - **유치한 감탄사·과장된 표현 금지.** 과장 형용사가 걸리면 지우는 게 아니라 **사실로 바꾼다.** 그 자리엔 원래 수·이름·조건이 들어갔어야 한다.
  - **이모지 금지.**
  - **em dash 같은 ai slop 이 느껴지는 표현도 없어야 한다.** 단 아래 "마커 정직성" 을 먼저 읽어라. 이건 증상 처리지 임무가 아니다.
- 커밋·push 는 사용자가 명시할 때만.

## 보호 구간 (불가침)
산문 규칙을 문서 전체에 기계적으로 걸면 **문서화된 명령이 깨지고 한국어 표기가 훼손된다.** 둘 다 가설이 아니라 실재한다.

### 코드: ` -- ` 함정
안티슬롭 지침은 산문의 이중하이픈(` -- `)을 em dash 대용으로 보고 지우라고 한다.
그런데 셸에서 ` -- ` 는 POSIX end-of-options 다. 이 저장소에도 그런 줄이 있다:

```
claude mcp add context7 -s user -- npx -y @upstash/context7-mcp
```

여기서 ` -- ` 를 지우면 뒤의 `-y` 를 `claude mcp add` 가 자기 옵션으로 먹으려 든다.
문서화된 MCP 설치 명령이 그대로 죽는다. 저장소 안에서 같은 모양이 여러 건 반복된다.

**산문의 이중하이픈과 이 ` -- ` 는 문자적으로 동일하다.** 정규식으로는 절대 구분되지 않는다.
**오직 펜스 인지만이 구분한다.**

보호 대상:
- 코드펜스 안 전부
- 인라인 코드 안 전부
- URL (하이픈·이중하이픈이 경로·쿼리에 들어간다)
- `--flag` 형태의 옵션 (산문에 맨몸으로 나와도)
- 표 안의 명령·경로 셀

**`sed`/`awk` 일괄 치환은 그 자체로 결함이다.** 펜스 상태를 모르는 도구로 문서 전체를 훑는 순간 위 구분이 사라진다.
편집은 읽고, 위치를 특정하고, **한 군데씩** 한다. 무엇을 왜 바꿨는지 셀 수 있어야 한다.

### 한국어 표기
영문 튜닝된 휴리스틱은 한국어 표기에서 오탐한다. 대표가 가운뎃점 U+00B7(`·`)이다.
한국어 문서는 이걸 나열 구분자로 쓴다(`설계·구현·검증`). 규칙이 이걸 특수문자 슬롭으로 잘못 걸면
한 군데가 아니라 문서 전역 수십·수백 군데가 한꺼번에 훼손된다.

화이트리스트를 먼저 세운다. 최소한 `·`(나열), `「」`·`『』`(인용·제목), `～`(범위), 전각 괄호·따옴표.
**한국어 문서에서 관용적으로 쓰이는 구두점은 슬롭이 아니라 표기다.** 지우기 전에 그게 이 문서의 언어에서 정상인지부터 판정한다.

## 마커 정직성
**단독 em dash 는 AI 증거가 아니다.** em dash 사용은 LLM 보다 훨씬 오래됐고 편집자·기자가 늘 쓴다.
신호는 **빈도**지 존재가 아니며, 다른 징후와 뭉쳐 나타날 때에만 의미가 있다.

인용 출처도 같은 경고를 한다. Wikipedia 의 "Signs of AI writing"(CC BY-SA)은 이 징후 목록을
**고쳐야 할 문제로 다루지 말라**고 명시한다. 이유는 품질이 아니라 탐지다: 목록대로 다듬으면 글이 좋아지는 게 아니라 탐지만 어려워진다.

그래서 이 스킬의 프레이밍은 안티슬롭이 아니다. 질문은 하나다: **"이 README 가 정확하고 간결한가."**
슬롭은 **증상**으로 다룬다. 과장된 형용사는 "AI 티가 난다"라서 고치는 게 아니라 **그 문장이 사실을 안 말하고 있어서** 고친다.
사실을 말하는 문장이 우연히 마커를 하나 밟았다면 그건 고칠 대상이 아니다.

**마커 목록을 여기에 옮겨 적지 마라.** `humanizer` 가 이미 그 목록을 갖고 있고, humanizer 자신도 그 안에서 갈라져 있다
(한 곳은 em dash 를 hard constraint 라 하고, 다른 곳은 단독 em dash 는 증거가 아니라고 한다).
여기서 재서술하면 banker 가 **서로 모순되는 사본 3개**를 지게 된다. 마커 판단이 필요하면 humanizer 를 읽고 위임한다.

## 워크플로

### 0. 대상 확정
```bash
git rev-parse --show-toplevel
git ls-files | grep -i 'readme'
```
- 기본 대상은 저장소 루트의 README 하나다.
- 여러 개면(모노레포 패키지별 등) 목록을 제시하고 **어느 것을 갱신할지 확인받는다.** 전부 훑어 diff 를 부풀리지 마라.
- README 가 없으면 여기서 멈춘다. 작성은 이 스킬이 아니다.

### 1. 산문 주장 추출 (README 쪽)
README 를 **끝까지 읽고** 검증 가능한 주장을 뽑는다. 주장 = 사실이 뒷받침해야 하는 문장.
- **수량**: 개수·버전·크기
- **고유명**: 스킬·커맨드·모듈·명령 이름
- **경로**: 파일·디렉터리
- **동작**: 설치·실행 방법
- **요구사항**: 런타임·의존성

수량 주장은 문서 전역에서 **전부** 찾는다. 한 곳만 고치면 다음 릴리스에 문서 내부끼리 어긋난다.
```bash
grep -nE '[0-9]+ *(개|files|skills|commands)' README.md
```

### 2. 사실 수집 (코드 쪽)
사실의 위치는 저장소마다 다르다. 판정 기준은 하나다: **빌드·설치·테스트가 실제로 읽는 파일이 사실이다.**
흔한 곳은 패키지 매니페스트(버전·의존성·엔트리포인트·스크립트), 배포 매니페스트(실제로 배포되는 표면 목록),
소스 트리(디렉터리와 파일이 곧 사실), CI 설정(실제로 도는 명령).

이 계열 저장소의 예:
```bash
ls -d skills/*/ | wc -l              # 디렉터리 수. 이게 스킬 수라고 단정하지 마라
ls -d skills/*/SKILL.md | wc -l      # 런타임이 실제로 세는 것
node -e "const m=require('./codex/manifest.json');console.log(m.surfaces.filter(s=>s.type==='skill').length)"
node -e "const p=require('./package.json');console.log(p.version, JSON.stringify(p.dependencies||{}))"
```

**앞의 두 줄이 갈리면 그 차이가 사실이다.** 이 저장소에서 실제로 갈린다: 디렉터리는 55 인데 `SKILL.md` 보유는 54 이다.
`skills/ultra-init-workspace/` 는 런타임 산출물 디렉터리라 `SKILL.md` 가 없고, 그래서 배포 매니페스트에도 없고 `package.json` `files[]` 도 negation 으로 뺀다.
즉 "디렉터리를 세면 스킬 수" 라는 그럴듯한 가정이 **여기서 1 을 더 센다.** 세 곳(매니페스트·`files[]`·테스트의 `SKILL.md` 필터)이 이미 54 를 말하는데 디렉터리 카운트만 55 라면, 틀린 쪽은 카운트다.

**README 는 어떤 경우에도 사실이 아니다. 그리고 사실을 세는 명령도 틀릴 수 있다. 세 소스가 같은 값을 말할 때만 통과다.**

### 3. 대조 (삼각검증)
이 대조가 이 스킬의 **유일한 신규 능력**이다. 나머지(문체·슬롭)는 다른 스킬이 이미 한다.
주장마다 사실을 붙여 표로 만든다. 산문 주장 ↔ 매니페스트 ↔ 소스 트리가 같은 값을 말해야 통과다.

| README 주장 | 위치 | 코드 사실 | 근거 | 판정 |
|---|---|---|---|---|
| "스킬 42개" | 10행·131행 | 53 | `ls -d skills/*/SKILL.md` = 54, 매니페스트 skill 표면 = 54 (디렉터리 카운트는 55 라 셋 중 혼자 다르다) | 드리프트: 2곳 다 고침 |
| "`--fast` 지원" | 60행 | 없음 | 파서에 해당 플래그 없음 | 드리프트: 문장 삭제 |
| "Node 18+ 필요" | 20행 | `engines.node: ">=18"` | package.json | 통과 |

(표는 예시다. 주장·사실·근거·판정 4열이 본질이고 행은 그 저장소에서 나온다.)

**흔한 실례:** 산문에 "스킬 N개" 같은 수를 하드코딩해두고 그 수가 **어떤 테스트와도 묶여 있지 않은** 경우다.
스킬을 하나 추가해도 CI 는 초록이고 README 만 조용히 틀려진다. 릴리스마다 오차가 벌어지지만 아무도 실패를 보지 못한다.

판정은 3종:
- **통과**: 주장 = 사실.
- **드리프트**: 주장 ≠ 사실 → 고친다.
- **Unknown**: 사실 쪽에 대응하는 게 없다 → **지어내지 말고** 사용자에게 올린다.

**대조는 양방향이다.**
- README 에만 있는 것 = **유령**. 지워진 기능이 문서에 남았다.
- 코드에만 있는 것 = **누락**. 추가된 기능이 문서에 없다. 이쪽을 더 자주 놓친다. README 를 읽는 것만으로는 절대 안 보이기 때문이다.

### 4. 갱신
- 3단계에서 **드리프트 판정이 난 문장만** 고친다.
- 고쳐 쓸 때 위 "고정 정책" 의 품질 기준 4개를 지킨다.
- 편집은 한 군데씩. 보호 구간을 지난다.
- 수량 주장은 발견한 **모든 위치**를 같은 커밋에서 고친다.

### 5. 검증 (보고 의무)
**검증은 재대조다.** 고쳤다는 기억이 아니라 **명령을 다시 돌린 결과**로 판정한다. 라이브러리는 필요 없다.

1. **주장 재대조** (본 검증): 2단계 사실 수집 명령을 **전부 다시 돌려** 갱신된 문장과 맞춘다.
2. **옛 값 잔존 0**: 수량 주장은 문서 전역이다. 무관한 매치는 눈으로 배제하고, 남은 게 옛 값이면 아직 안 끝났다.
```bash
grep -n '42' README.md
```
3. **코드 무손상 (필수)**: diff 를 **전수로** 읽는다. 코드펜스·인라인 코드·URL·`--flag` 에 걸린 변경은 **하나도 없어야 한다.** 사실 정정으로 명령 자체가 바뀐 경우가 아니면 전부 회귀다. 하나라도 설명하지 못하면 되돌린다.
```bash
git diff -- README.md
grep -c '^```' README.md   # 갱신 전과 같아야 한다(펜스는 짝수)
```
4. **한국어 표기 무손상**: 감소분이 "지운 문장 몫" 으로 설명돼야 한다. 설명되지 않는 감소는 규칙이 오탐한 것이다. 즉시 되돌린다.
```bash
grep -c '·' README.md   # 갱신 전 값과 비교
```
5. **경로 실재**: MISSING 이 나오면 그것도 드리프트다(파일이 옮겨졌거나 지워졌다).
```bash
grep -oE '\]\([^)]+\)' README.md | cut -c3- | cut -d')' -f1 \

### 6. 리포트 (4-field)
**변경 파일**(README 만) / **드리프트 표**(주장 → 사실 → 근거 → 조치) / **검증**(재대조 결과·코드 무손상·표기 카운트 비교) / **Unknown**(코드에 근거가 없어 판정 못 한 주장. 사용자 확인 필요).
커밋은 "push" 대기로 명시한다.

## 함정
- **README 를 근거로 README 를 고치는 것.** 문서 안에서 아귀가 맞아도 코드와 틀릴 수 있다. 사실은 항상 코드 쪽에 있다.
- **`sed`/`awk` 일괄 치환.** 펜스 상태를 모르는 도구는 산문의 이중하이픈과 셸의 ` -- ` 를 구분하지 못한다. 위험이 아니라 결함이다.
- **누락 방향을 안 보는 것.** README 만 읽으면 "코드에 있는데 문서에 없는 것" 은 절대 안 보인다.
- **수량 주장을 한 곳만 고치는 것.** 같은 수가 여러 곳에 흩어져 있다. 다음 릴리스엔 문서 내부끼리도 어긋난다.
- **전면 재작성.** 드리프트 3건을 고치겠다고 문서를 다 다시 쓰면 검토가 불가능해지고 새 오류가 섞인다.
- **영문 휴리스틱을 한국어에 그대로 거는 것.** `·` 같은 표기가 대량 훼손된다.
- **마커 목록을 여기서 재서술하는 것.** humanizer 에 위임한다. 사본이 늘면 모순이 늘고, 그 모순은 이미 실재한다.
- **슬롭 제거를 임무로 착각하는 것.** 임무는 정확성이다. 정확한 문장이 우연히 마커를 밟았다고 고치면 문서만 나빠진다.
- **파서 라이브러리 도입.** dependencies 0 을 지킨다. 지시문과 `grep` 으로 푼다.
- **범위 밖 파일에 손대는 것.** SKILL.md·CHANGELOG 는 이 스킬이 아니다.
- **없는 사실을 지어내 채우는 것.** 코드에 근거가 없으면 Unknown 이다.

## 원칙
- 임무는 정확성이다. 문체는 갱신물의 품질 기준이지 목적이 아니다.
- 사실은 코드에 있다. README 는 어떤 경우에도 사실이 아니다.
- 대조는 양방향이다. 유령과 누락을 같이 본다.
- 편집은 한 군데씩. 일괄 치환 금지.
- 보호 구간(펜스·인라인 코드·URL·플래그)은 불가침이다.
- 한국어 표기는 슬롭이 아니라 표기다. 지우기 전에 언어를 판정한다.
- 판정은 재대조로 한다. 기억 금지.
- 근거 없는 주장은 Unknown 으로 올린다. 지어내지 않는다.
- 마커 판단은 humanizer 소관이다. 여기서 사본을 만들지 않는다.
- 무의존으로 푼다.

ARGUMENTS: [--check] [README 경로] (없으면 저장소 루트 README 를 대조 → 갱신 → 재대조)
- `--check`: 아무것도 고치지 않는다. 대조만 돌려 드리프트 표와 Unknown 만 보고한다.
- README 경로: 대상을 특정한다(모노레포에서 패키지 README 를 지정할 때).
